### 1.8.13

> 打印省纸收尾：修掉「打印预览里一大片空白、却还是分了 2 页」。

- **现象**（你发的截图）：发放汇总清单打印出来 **2 页**，第 2 页只有「打印日期」一行、其余全空。
- **为什么**：纸面内容比一页只多 ~12mm，多出来的全是「屏幕上舒服、纸上是浪费」的内边距：
  表格每格上下 4px（31 行 ≈ 33mm）、单据自己再套一层 `p-4`（≈8mm）、尾部「打印日期」还带 `mt-4`。
- **改法**（只动 `src/styles.css` 的打印协议，**屏幕观感零变化**）：打印态把表格单元格纵向内边距压到 1px、
  单据内边距压到 `2mm 3mm`、尾部段落 `margin-top: 1mm` 且不许单独另起一页；另外**没有待发放记录时
  不再印「无日期的待发放记录按当前年份显示」那行**（它正好是压垮第一页的最后一行）。
- **实测**（真 A4 PDF）：30 人 140 笔的汇总清单 **2 页 → 1 页**；45 人明细 **6 → 5 页**；
  工资条（9 个月 + 14 笔打款）**4 → 2 页**（改前每人多一页只印签字行）。
- 内容本身超过一整页的（如 2 人 26 笔明细 ≈ 285mm）仍是 2 页——那是纸真不够，不是留白没压干净。

### 1.8.12

> 打印口径细化：**一条 = 一个人 / 一份单据** —— 整条放得下就并排塞满，放不下才另起一页。

- 你的口径：「能单独一页的就不要和别的混到一起」＋「如果第一页有空白，第二条能全部打到第一页就 2 条打到一起，
  反之就另开一页，后边依次类推」。
- **现在**：发放明细里**每个人的一整节**、合同对账单里**每份合同**都整条不拆 ——
  放得下就与上一条并排塞满、放不下才整条去下一页；比一整页还高的条（几十条明细的合同）自己跨页续排。
- **实测**（真浏览器出 A4 PDF）：2 人 26 笔 → 明细 2 页，第 1 页留白 **0.1mm**、第 2 页是第 2 个人整节，
  **没有任何人被拆到两页**；3 人 27 笔 → 2 页；45 人 45 笔 → 6 页（前 5 页留白 0.1mm，比上版更满）；
  合同对账单：第一份合同自己续排，**第二份合同独占一页**（改前是两份混在第 1 页）。
- 页数与 1.8.11 完全一致，只是不再拆人/拆单据。

### 1.8.10

> 修「打印分页留白」：发放记录 26 条打印汇总/明细时，第一页空一大片、尾巴被整体推到第二页。

- **现象**（用户实测）：「发放记录汇总，26 条记录打印汇总就会分页，第一页还有很多空缺就会把尾巴放在第二页」。
- **为什么**：打印件里用了**容器级**「整块不许拆页」（每个人的明细一节、整张对账单），
  页底放不下就把整块推到下一页 —— 实测 26 笔 / 2 人 + 代收折行时，**第一页留白 112.3mm**；
  另外应用外壳的 `min-h-screen/min-h-dvh` 在打印态也生效（容器至少一屏高），是「提前断页」的经典成因。
- **现在**：
  - **每页尽量填满**（除最后一页）：26 笔 / 2 人的明细第一页留白 **112.3mm → 4.6mm**，
    26 笔 / 5 人 **50.9mm → 2.8mm**，**合同对账单 50.1mm → 0.1mm**；
  - **跨页有表头**：明细/汇总表在第二页起照样印表头（8 列 / 5 列逐字对得上），
    合计行仍在表格最后（`<tfoot>`，不会被拆开）；
  - 明细清单**允许在人与人之间分页**，一个人记录多也不会再让上一页空一大片。
- 打印内容、口径、合计、代收标注**一个字没改**，只改分页；报销单 / 保险合同清单 / 工资条
  复查过没有同类问题（工资条仍是刻意的「一张/两张一页 + 裁切线」）。
- 测试 **384 → 387**（新增 3 条打印分页守卫：打印态一屏高必须清零、打印表格必须表头跨页重复、
  不许容器级 `break-inside-avoid`，并带坏样本自检），Excel 往返 70/70，四道闸全过。

### 1.8.8

> 修 C 组（合同/保险/查询/影像/导入导出/移动端，6 条）与 B 组（人员/考勤/发放/报销，5 条）

- **【数据可信】发放「导出 → 导入」不再多记一笔**：以前导出文件里的日期是原样写的

### 1.7.10

- **找到「一键更新一直不生效」的真正原因并修掉**：更新容器要执行的那段脚本是**语法错误**的 —— 脚本用模板字符串生成，里面写的 `"\n"` 被模板字符串变成了真换行，生成的 .cjs 里字符串字面量跨行，node 解析阶段就 SyntaxError 退出，容器又被自动删除，于是界面只看到「已受理」、实际什么都没换、日志里一个字都没有。（1.7.6 修的是「创建更新容器时请求体被丢掉」，那之后容器能创建了，但脚本本身跑不起来。）现在脚本用 `log()` 统一写日志、并新增**语法守卫测试**（把生成的脚本真的交给 JS 引擎解析一遍），这类错误不会再溜过去。

### 1.7.9

- **更新会自动绕开"加速站缓存"**：拉镜像时优先按 `<仓库>:sha-<main 最新提交>` 这种一次性标签拉（加速站不缓存它，只能回源，基本一定是最新构建），再退回 `latest`。
- **拉完核对镜像里的版本**：起一个只跑 `cat /app/VERSION.txt` 的临时容器（读完立刻删），版本不比本机新就换下一个源，全都不新就报错并停止更新（容器、台账不动）。日志和「上次更新结果」里都会写明"镜像内版本 X"，一眼能看出是加速站发了旧镜像而不是程序坏了。

### 1.7.8

- **「更新成功、重启后版本没变」不再发生**：拉完镜像先按镜像 ID 比对，如果拉到的就是当前正在跑的那个镜像（镜像加速站缓存还没刷新），自动改试 ghcr.io 直连；所有源都还是旧的就明确报错并**停止更新**（容器、台账都不动），不再白重启一次。
- **更新时顺手清理 NAS 上的旧镜像**（一份镜像几百 MB）：换容器成功后自动删掉上一个版本的镜像；另新增「清理旧镜像」按钮（设置 → 软件更新 / 版本号弹窗，管理员），先告诉你能清几个、多少 MB，确认后再删，只删本项目且「没被任何容器引用」的镜像。
- 不存在的日期不再入库：`2026-02-31`、`2026-04-31`、平年 `2026-02-29` 一律判空（闰年 2/29 仍合法）。以前只查「日 ≤ 31」，这类日期会被 `new Date()` 静默进位成 3/3，出勤天数被凭空放大——`daysBetween("2026-01-01","2026-02-31")` 原来算出 62 天。

## 飞牛 NAS

目录固定：`/vol1/1000/docker/attendance/`  
`data` 已经有台账的，解压软件时不要覆盖、不要删除 `data`。

本机构建（推荐）：

```bash
cd /vol1/1000/docker/attendance
chmod +x 一键部署.sh 一键拉取.sh 初始化目录.sh
./一键部署.sh
```

打开 `http://NAS的IP:8501`，左下角应显示当前版本号（以 `VERSION.txt` 第一行为准）。

拉 GitHub 镜像（Actions 全绿，并且 Packages 里 `gongdi-ledger` 已设 Public）：

```bash
./一键拉取.sh
```

`./一键拉取.sh` 会优先用 `docker-compose.github.yml`（国内加速），没有才用 `docker-compose.yml`。

国内镜像：`ghcr.1ms.run/qq987985/gongdi-ledger:latest`  
compose 文件对照：

| 文件 | 镜像源 | 说明 |
|---|---|---|
| `docker-compose.yml` | `ghcr.1ms.run/...` | **默认，国内加速** |
| `docker-compose.github.yml` | `ghcr.1ms.run/...` | 和上面相同，老脚本兼容用 |
| `docker-compose.ghcr.yml` | `ghcr.io/...` | GitHub 官方源，国内可能拉不动 |
| `docker-compose.build.yml` | 本机构建 | 网络极差或想自己改代码时用 |

compose **只挂 data**，不要再挂 `VERSION.txt`。国内网络建议直接用 `docker-compose.yml`。已经启动过旧容器的，用 `./一键拉取.sh` 即可，数据不会动。

本机构建镜像名：`gongdi-ledger:<当前版本号>`，端口 `8501:8080`。

```text
│   ├── ic/                   旧版公共目录：张三-IC卡.jpg
│   └── 报量单/ 发票/ 收款回单/ 考勤影像/ 合同扫描件/ 报销凭证/ 报销打款/   旧版公共目录（只读回落）

```

> 旧版公共目录里的影像仍能被读到（只读回落），在设置页点「影像归入本台账」可复制进各台账自己的目录；

## 合同扫描件

1. 打开「合同管理」
2. 先填 **项目名称**
3. 点表格里的项目名称（或新增合同），页面滚到下方
4. 「保存合同信息」**正下方**有虚线框「合同电子版」，点绿色按钮或拖入 PDF / 照片

保存规则：

- 磁盘文件名是 **项目名称-合同电子版**，例如项目叫「某某住宅」，上传后是 `某某住宅-合同电子版.pdf`
- 存在本台账自己的影像目录 `data/photos/<台账编号>/合同扫描件/`（1.7.3 起按台账隔离；旧版公共目录里的文件仍能读到）
- **上传成功立刻算有合同**，不用再点保存。列表里 **有合同 / 无合同** 看有没有这个文件
- 把 PDF 直接拷到这个目录、文件名符合规则，打开软件也会自动认成有合同
- 没有合同：不要单独填原因，写在备注里即可
- 上传前必须先有项目名称，否则会提示先填项目名称
- 点「保存合同信息」会弹出确认窗，列出这次改了哪些项

## 常见问题

**打开变成 `{"status":500,"unhandled":true,"message":"HTTPError"}`**  
1.0.0 / 1.0.1 拉镜像或打包不完整会这样。用本机构建 `./一键部署.sh`。若 `data/VERSION.txt` 是文件夹，脚本会删掉这个名字。

**网页一直转圈**  
`docker rm -f attendance-app` 再 `./一键部署.sh`。不要删 data。

**找不到上传合同扫描件的地方**  
点表格里的项目名称，页面滚到下方，「保存合同信息」正下方的虚线框。先填项目名称再上传。保存后文件名是 `项目名称-合同电子版.pdf`。

**国内 pull ghcr.io 失败 EOF / 403**  
改用 `ghcr.1ms.run/qq987985/gongdi-ledger:latest`，并把 Packages 设为 Public。不行就继续本机构建。

**GitHub 网页拖文件没反应**  
一次超过 100 个文件。分两次 Commit，或用 Git 客户端。

**Windows 点更新没反应**  
Releases 里要先有比本机新的 `gongdi-windows.zip`。NAS 没有「点更新」，用脚本重建或拉取。
