镜像：


> ⚠️ 多设备请勿同时编辑同一本台账：账本数据在两台设备间是全量同步（无版本冲突提示），同时改动会互相覆盖。建议一台电脑/手机上录入，其他设备只读查看。

1. `VERSION.txt` 第一行
2. `VERSION.txt` 加一节说明（网页左下角只显示最近 10 条）
3. 本 README 这一节

### 1.7.13

- 一次全量功能走查（服务端接口 + 权限矩阵 + Excel 往返 + 页面手动走查）确认并修复了 **26 个问题**，其中值得你知道的：
  - **导出页「总台账」以前点了必 404**（客户端和服务端的名字不一致），现在修好了。
  - **权限**：新建账户以前完全忽略你选的权限（一律给"只读"整套）；只有"成员管理"权限的人可以给自己提权成全部权限 —— 两个都堵了。
  - **操作记录**在文件损坏时不再被一次写入覆盖掉历史（以前会从 97 条变成 1 条）。
  - **年份**不会被非法输入写坏（以前 `year=abc` 会把台账年份写成空）。
  - **Excel 往返**一批修复：恢复旧年备份不再落到今年、重复导入不再把发放/报销翻倍、手填的 `1,200`/`¥300`/`300元`/`22天` 不再被清成 0、「总计」行不再被当成真数据、合同的扫描件/有无合同/无合同原因不再丢、在保人员不再被写成「已结束」等。
  - **健壮性**：发错格式的请求不再 500、超长文件名不再 500、伪造的超大请求体不再挂住连接、未捕获异常也会写进 `data/logs`。
- 新增 5 条接口约定守卫测试，并把 70 用例的 Excel 往返套件搬进仓库：`pnpm run test:roundtrip`（改 Excel 相关代码时请连它一起跑）。

### 1.7.12

- 关于 `gongdi-updater` 这个容器：它是**一键更新时临时起的容器**（不是镜像），替换完就退出；1.7.10 起故意不自动删除，是为了失败时还能看它的日志（「查看更新日志」里那句「更新容器：已退出（exit N）」就是它）。**它随时可以手动删**，不影响台账、也不影响下次更新。
- 「清理旧镜像」现在会顺手删掉这个临时更新容器 —— 否则它作为「已停止的容器」会把上一次更新用的镜像一直占住，那个镜像就永远删不掉。统计「镜像被谁占用」时也会忽略已退出的更新容器。

### 1.7.11

- 人员导出/导入不再丢**调薪历史**：人员信息表新增「工资历史」列（一段可读的 JSON），导出再覆盖导入会原样回来，不会再出现「导出备份 → 改两个人 → 覆盖导入」把调薪历史静默清空的情况。该列被手改坏时按「没有历史」处理，不影响同一行人员的其它字段。

### 1.7.10

- **找到「一键更新一直不生效」的真正原因并修掉**：更新容器要执行的那段脚本是**语法错误**的 —— 脚本用模板字符串生成，里面写的 `"\n"` 被模板字符串变成了真换行，生成的 .cjs 里字符串字面量跨行，node 解析阶段就 SyntaxError 退出，容器又被自动删除，于是界面只看到「已受理」、实际什么都没换、日志里一个字都没有。（1.7.6 修的是「创建更新容器时请求体被丢掉」，那之后容器能创建了，但脚本本身跑不起来。）现在脚本用 `log()` 统一写日志、并新增**语法守卫测试**（把生成的脚本真的交给 JS 引擎解析一遍），这类错误不会再溜过去。
- **更新容器不再一声不响地死掉**：任务改走环境变量、脚本走 Cmd 内联（不再依赖 data 挂载）；启动两秒后检查它是否还活着，退出了就当场报错并贴出它的输出；不再自动删除，失败后点「查看更新日志」能看到「更新容器：已退出（exit N）」+ 它自己的输出。

### 1.7.9

- **更新会自动绕开"加速站缓存"**：拉镜像时优先按 `<仓库>:sha-<main 最新提交>` 这种一次性标签拉（加速站不缓存它，只能回源，基本一定是最新构建），再退回 `latest`。
- **拉完核对镜像里的版本**：起一个只跑 `cat /app/VERSION.txt` 的临时容器（读完立刻删），版本不比本机新就换下一个源，全都不新就报错并停止更新（容器、台账不动）。日志和「上次更新结果」里都会写明"镜像内版本 X"，一眼能看出是加速站发了旧镜像而不是程序坏了。

### 1.7.8

- **「更新成功、重启后版本没变」不再发生**：拉完镜像先按镜像 ID 比对，如果拉到的就是当前正在跑的那个镜像（镜像加速站缓存还没刷新），自动改试 ghcr.io 直连；所有源都还是旧的就明确报错并**停止更新**（容器、台账都不动），不再白重启一次。
- **更新时顺手清理 NAS 上的旧镜像**（一份镜像几百 MB）：换容器成功后自动删掉上一个版本的镜像；另新增「清理旧镜像」按钮（设置 → 软件更新 / 版本号弹窗，管理员），先告诉你能清几个、多少 MB，确认后再删，只删本项目且「没被任何容器引用」的镜像。
- 不存在的日期不再入库：`2026-02-31`、`2026-04-31`、平年 `2026-02-29` 一律判空（闰年 2/29 仍合法）。以前只查「日 ≤ 31」，这类日期会被 `new Date()` 静默进位成 3/3，出勤天数被凭空放大——`daysBetween("2026-01-01","2026-02-31")` 原来算出 62 天。
- 调薪生效日没补零（如 `2026-7-1`）现在也能当月生效：字符串比较会把它排到 `2026-07-31` 之后，导致那条调薪当月读不到、工资静默回退成当前工资。现在比较前统一补零，并容忍 `2026.7.1` / `2026年7月1日` 等写法。
- 身份证 16/17 位不再被当成「还没输完」放行：以前会存进人员资料，且生日/性别按 15 位解析出错。现在提示「应为 15 位或 18 位（现在是 N 位）」。


### 1.7.7

- 更新卡片里直接显示「上次更新结果」：成功/失败、开始与结束时间、失败原因一句话；失败时还会说明「容器仍在旧版本上跑、台账数据没动」，不用再靠猜。

### 1.7.4

- **反代环境下的更新失败已修**：更新改为「立刻返回 + 后台执行 + 前端轮询进度」，不再挂一个几分钟的长请求（反代 nginx 默认 60s 就会掐断它并回 HTML 504 → 界面只能显示「更新失败」）；同源校验也兼容反代（接受 `X-Forwarded-Host`）。
- 修复「一键更新」报「更新失败」却查不出原因：失败原因不再被兜底文案吞掉，请求中断会轮询核对真实版本；服务端与容器内更新脚本都写 `data/logs/update.log`，失败另写 `data/.gongdi-update-error.txt`。
- 飞牛（Docker）更新重建容器更稳：不再把整份网络配置喂回 Docker API（只按网络名挂载，避免 `invalid endpoint settings`）；顺序改为「创建新容器 → 停老容器 → 启动新容器 → 成功后才删老容器 → 改名接管」，任一步失败自动回滚到老容器，不再出现「更新失败后应用消失」。
- Docker 更新改为「先创建新容器，再停旧容器」：配置/挂载有问题时旧容器还在，不会更新失败即停服。
- Windows 解压版更新：先让响应发回浏览器再退出进程，不再因响应被切断而误报失败。

## 飞牛 NAS

目录固定：`/vol1/1000/docker/attendance/`  
`data` 已经有台账的，解压软件时不要覆盖、不要删除 `data`。

本机构建（推荐）：

```bash
cd /vol1/1000/docker/attendance
chmod +x 一键部署.sh 一键拉取.sh 初始化目录.sh
./一键部署.sh
```

打开 `http://NAS的IP:8501`，左下角应显示 **1.2.38**。

拉 GitHub 镜像（Actions 全绿，并且 Packages 里 `gongdi-ledger` 已设 Public）：

```bash
./一键拉取.sh
```

`./一键拉取.sh` 会优先用 `docker-compose.github.yml`（国内加速），没有才用 `docker-compose.yml`。

国内镜像：`ghcr.1ms.run/qq987985/gongdi-ledger:latest`  
compose 文件对照：

| 文件 | 镜像源 | 说明 |
|---|---|---|
| `docker-compose.yml` | `ghcr.1ms.run/...` | **默认，国内加速** |
| `docker-compose.github.yml` | `ghcr.1ms.run/...` | 和上面相同，老脚本兼容用 |
| `docker-compose.ghcr.yml` | `ghcr.io/...` | GitHub 官方源，国内可能拉不动 |
| `docker-compose.build.yml` | 本机构建 | 网络极差或想自己改代码时用 |

compose **只挂 data**，不要再挂 `VERSION.txt`。国内网络建议直接用 `docker-compose.yml`。已经启动过旧容器的，用 `./一键拉取.sh` 即可，数据不会动。

本机构建镜像名：`gongdi-ledger:1.2.38`，端口 `8501:8080`。

- **上传成功立刻算有合同**，不用再点保存。列表里 **有合同 / 无合同** 看有没有这个文件
- 把 PDF 直接拷到这个目录、文件名符合规则，打开软件也会自动认成有合同
- 没有合同：不要单独填原因，写在备注里即可
- 上传前必须先有项目名称，否则会提示先填项目名称
- 点「保存合同信息」会弹出确认窗，列出这次改了哪些项

## 常见问题

**打开变成 `{"status":500,"unhandled":true,"message":"HTTPError"}`**  
1.0.0 / 1.0.1 拉镜像或打包不完整会这样。用本机构建 `./一键部署.sh`。若 `data/VERSION.txt` 是文件夹，脚本会删掉这个名字。

**网页一直转圈**  
`docker rm -f attendance-app` 再 `./一键部署.sh`。不要删 data。

**找不到上传合同扫描件的地方**  
点表格里的项目名称，页面滚到下方，「保存合同信息」正下方的虚线框。先填项目名称再上传。保存后文件名是 `项目名称-合同电子版.pdf`。

**国内 pull ghcr.io 失败 EOF / 403**  
改用 `ghcr.1ms.run/qq987985/gongdi-ledger:latest`，并把 Packages 设为 Public。不行就继续本机构建。

**GitHub 网页拖文件没反应**  
一次超过 100 个文件。分两次 Commit，或用 Git 客户端。

**Windows 点更新没反应**  
Releases 里要先有比本机新的 `gongdi-windows.zip`。NAS 没有「点更新」，用脚本重建或拉取。
