# 工地台账 · 常见问题解答（FAQ）

> 面向使用的人，按「现象 → 为什么 → 怎么办」写。照着做就行，不需要技术背景。
> 版本以 `VERSION.txt` 第一行为准；软件左下角能看到当前版本。
> 请先记住一条：**任何情况下都不要删 `data` 目录**（删了等于把工地的账全删了）。

---

## 1. 更新后版本没变（点了更新，版本号还是旧的）

**现象**：点「更新」后提示成功/已受理，页面也重启了，但左下角版本号还是旧版本。

**为什么**：最常见的不是软件坏了，而是**镜像加速站还在发旧镜像** —— 容器确实换过了，但换上去的还是旧版本。
更新卡片现在会明确写出「本次拉到的镜像就是 X.X.X」，就是这种情况。

**怎么办**：

1. 打开 `设置 → 软件更新 → 查看更新日志`，看最后几行：
   - 有「本次拉到的镜像就是 旧版本」→ 等 5～10 分钟，让加速站刷新，再点一次「更新」。
   - 有「更新容器：已退出（exit N）」→ 把日志发给维护的人（这是更新过程本身的错误）。
2. 还是不行就让维护的人试一次 `./一键拉取.sh`，或直接在本机构建：`./一键部署.sh`。
3. 确认版本号位置：**以 `VERSION.txt` 第一行为准**，界面左下角显示的也是它。

> 升级只换程序，`data` 不动。放心多点几次「更新」，不会弄丢数据。

## 2. 图片 / 照片上传失败

**现象**：点上传没反应，或提示「照片太大」「文件名太长」「照片数据格式不对」，或列表里看不到刚传的图。

**为什么**：单张照片最大 **20MB**、合同/文档单文件最大 **50MB**；
文件名太长（照片超过 120 字节、文档超过 180 字节）系统会直接拒绝；
另外从 1.8.1 起，**格式不对的图片会被明确拒绝（400）**，不会再出现「界面说成功、实际没存上」的情况。

**怎么办**：

1. **先看提示**（红字 toast）。提示里有具体原因，按提示改：
   - 「照片太大」→ 用手机相册自带功能压缩，或用电脑缩小尺寸后再传（一般现场照片 1～3MB 就够）。
   - 「文件名太长」→ 把文件名改短（例如把一整串编号改成「张三-身份证」）。
   - 「格式不对」→ 确认传的是图片本身（jpg/png/webp），不是把图片放进 Word/PDF 再传。
2. **上传后列表里没有**：
   - 先刷新页面（F5）。
   - 如果照片是**手工拷进 NAS 目录**的，页面最多 3 秒后才会看到（软件会缓存目录列表，正常上传是立即生效的）。
   - 确认文件名符合规范：`张三-身份证-正面.jpg`、`张三-身份证-反面.jpg`、`张三-银行卡.jpg`
     （姓名要和「人员」里登记的**完全一致**，多余的空格、符号都会导致对不上）。
3. **合同扫描件**要先把「项目名称」填好再上传；列表里「有合同/无合同」就是看有没有这个文件。

> 传之前建议先本地看一眼图能不能正常打开：坏文件传上去也没法预览。

## 3. 保存时提示冲突（「服务器上的台账已被其他设备修改」/ 409）

**现象**：保存时弹出「服务器上的台账已被其他设备修改」，或者莫名变成 409 错误。

**为什么**：这是**有意的保护**。台账按服务器上的版本号校验，如果在你编辑期间**别的设备也保存过**，
软件不会悄悄用你这份把对方的改动覆盖掉，而是让你自己选。

**怎么办**：弹窗里只有两个选择，看清楚再点：

- **确定 = 用本机数据覆盖服务器**：你在本机的改动会保留，**对方刚才的改动会被覆盖掉**。
  只有确认「对方那次改动不要紧/可以重录」时才选它。
- **取消 = 放弃本机改动，加载服务器上的版本**：你这次没保存的内容会丢，但服务器上是对方的最新版本。
  想保留你改的内容，可以先截图或抄下来，加载后再补录。

**怎么避免**：

- **固定一台设备录入**，其他设备只查看（只读）。
- 两个人要同时改，就**分模块错开**（一个改考勤、一个改合同），保存前先说一句。
- 保存后看到「已保存」再切页面；不要同时开两个标签页改同一本台账。

## 4. 提示权限不够 / 登录后看不到数据

**现象**：「权限不足」「只有管理员能…」，或者登录成功但人员、合同页面是空的。

**为什么**：账号是按模块授权的。**要看人员数据需要「人员」权限**（人员里含身份证、银行卡等敏感信息），
合同、报销、保险、照片、查询、设置各是各自的权限。只给了「合同」权限的账号，是看不到人员列表的。

**怎么办**：

1. 让**管理员**到 `设置 → 账号`（成员权限）里，给你补上需要的模块权限，保存后**重新登录**生效。
2. 需要改数据（新增/编辑/删除）时，除了「查看」还要有对应的「编辑」权限。
3. 导出、备份、更新、清空数据这类操作**只有管理员**能做，这是刻意限制。
4. 权限预设与你实际需要的对不上时，直接让管理员改成**自定义勾选**，比套预设更准。

> 找不到「设置」菜单、或菜单比别人少几项，同样是权限问题，不是软件坏了。

## 5. 数据怎么备份、怎么迁移到另一台机器 / 新 NAS

### 备份（建议每月一次）

1. **软件内**：`设置 → 数据 → 立即备份 Excel` → 文件落在 `data/backups/`。
2. **导出**：`导出 → 全部年份 → 总台账` → 得到一个 Excel，存 U 盘或私有网盘。
3. **最彻底**：把整个 **`data` 目录**复制一份到移动硬盘或另一块盘 —— 账号、台账、照片、
   合同扫描件、历次备份、日志全在里面。**拷走它就等于拷走了全部数据。**

### 迁移到另一台机器 / 新 NAS

1. 在旧机器上把整个 **`data` 目录**拷出来（先停止软件更稳妥：`docker stop 容器名`，Windows 直接关掉窗口）。
2. 在新机器上装好同版本软件（或更新到同版本）。
3. 把 `data` 目录放到原来对应的位置（Windows：解压目录下；NAS：`/vol1/1000/docker/attendance/data`）。
4. 启动软件，账号、台账、照片、合同都应该原样回来。
5. 迁完**核对一遍**：人员条数、最近一个月的考勤、合同附件能不能打开。

> 注意：**Windows 的 `data` 和 NAS 的 `data` 互不相通**，不要混用，也不要用新机器的空 `data` 覆盖旧机器有数据的 `data`。
> 恢复时若提示「台账文件读取失败」，说明拷过去的 `data` 不完整（常见于只拷了 `books` 没拷 `photos`），
> 用完整备份重来一次。

## 6. 忘记管理员密码

**不要删 `data`**（那会把整个台账删掉）。用备份里的 `data/accounts`（账号目录）恢复：

1. 找到一份**还记得密码时**的备份（第 5 节的三种备份里任一份，含 `accounts` 目录）。
2. 停掉软件，用备份里的 `accounts` 覆盖现在的 `data/accounts`（**只覆盖这一个目录**，`books` 不要动）。
3. 启动软件，用备份时的密码登录，然后到 `设置 → 账号` 重设密码。

> 千万别在忘了密码时点「清空全部数据」—— 那是把工地的账一起清掉。

## 7. 打开网页一直转圈 / 一片白 / 显示 `{"status":500}`

**怎么办**（按顺序试）：

1. **刷新页面**（Ctrl+F5 强制刷新）。
2. **看日志**：`data/logs/` 里当天日期的 `.log` 文件，最后几行通常直接写了原因。
3. **重启软件**：飞牛 `docker restart 容器名`（或 `docker rm -f` 后重新 `./一键部署.sh`）；Windows 关掉窗口重新双击 `启动.bat`。
4. **确认 data 目录完整**：`data/accounts`、`data/books`、`data/photos` 都在。
   不要手建 `data/VERSION.txt`（会变成文件夹导致首页 500）。
5. 仍然不行就把 `data/logs/` 里的日志发给维护的人。**不要删 data、不要清空数据。**

> 大导出、备份这类操作页面会等几秒是正常的；超过 2 秒的慢请求会记进日志（`慢请求`），方便排查。

## 8. Excel 导入没反应 / 导入后条数不对

**怎么办**：

1. **先在「导入」页面下载对应模板**，照着模板填：**列名不要改**、不要加合并单元格、不要多行大标题。
2. 导入模式选对：
   - **增加**：在现有数据上追加，重复的（同姓名同年月等）会跳过并提示。
   - **替换**：清掉原有再导入。**替换前先备份**。
3. 常见「条数不对」的原因：
   - 「合计/总计」行被当成真实数据 —— 系统会自动跳过这类行，若仍异常请检查该行姓名列是否被填了内容。
   - 月份没识别出来 —— 请把 Excel 的 sheet 名写成含月份（如 `2026年3月考勤`），或在「月份」列里填数字。
   - 手填金额写成 `1,200`、`¥300`、`300元`、`22天` —— 这些现在都能正确读出来，不会再被当成 0。
4. 导入后**核对前 3 行**：姓名、金额、日期对不对。发现不对，用备份恢复后重导。

> 「已录月份」和「年度汇总」怎么算：**只填了备注（如整月「工伤休息」）也算这个月有记录**，
> 会计入「已录月份」并在年度汇总里列出（工天/金额为 0）。若某笔钱发给了本年没有考勤记录的人，
> 考勤页会提示「另有 N 笔 ¥X …」，总览的「已发放」包含这部分 —— 两处差额是因为表里只列有考勤的人。

## 9. 手机上表格看不全 / 按钮点不到

- 表格可以**左右滑动**查看（宽表是这样设计的，不会压扁内容）。
- 手机上底部是常用菜单（总览/考勤/合同/报销/查询），其它页面在左上角菜单里。
- 编辑弹窗在小屏上从底部弹出，**填一半想关掉时会先问你**，避免误触丢内容。
- 屏幕太小的时候，建议用平板或电脑做批量录入，手机只做查看和单条修改。
- 想打「按实际收款人」的发放清单：`发放记录` 页筛好范围后，在统计文字旁边选「全部实际收款人」
  或某一个人，点**打印明细**（逐笔 + 每人小计）或**打印汇总**（每人一行 + 总计）。只算填了
  发放日期的记录，待发放不算已发 —— 跟屏幕上的数字是同一套口径。

## 10. 「清空全部数据」点错了还能恢复吗

**能，只要之前做过备份，并且没有继续往里录新数据。**

1. 立刻**停止使用**（别让其他人再录），减少新数据被覆盖。
2. 用最近一次备份恢复：整份 `data` 覆盖回去，或只恢复 `data/books`（数字）+ `data/photos`（影像）。
3. 恢复后核对人员、考勤、合同附件。

> 「清空全部数据」需要管理员 + 输入密码 + 二次确认，是刻意做得很难误触。
> 日常不要点它，真要重新开始也请**先做一次完整备份**。

## 11. 台账数据会不会越来越大、保存越来越慢

- 1.8.1 起，保存时会**先压缩再上传**（中等工地的台账约 1MB 压到几十 KB），读取时也压缩回传，
  保存与打开都更快了；老浏览器不支持压缩会自动退回原样，不影响使用。
  - 如果压缩反而成了麻烦（例如要在反代/NAS 上抓包看请求），可以在容器里设环境变量 **`LEDGER_GZIP=off`**：
    关掉后读取不再压缩、本机保存也不再压缩，**但服务器仍然接受压缩上传**——别的设备上缓存了旧页面
    照样能保存，不会因为这一台关掉而报错。默认（不设）是开。
  - 上传整本台账有大小上限（**`LEDGER_MAX_MB`，默认 32MB**，指 gzip 解压之后的体积）；
    超过会被拒绝并在日志里留一条 warn，防止有人误传一个大文件把服务器撑爆。正常工地台账远低于这个数。
- 日志有上限（只留 14 天、单文件最多 8MB），不会把磁盘占满。
  1.8.4 起单文件写满会**自动滚动**成 `2026-09-16.log.1`、`.2`……（不再停写、当天的现场不会丢），
  滚动出来的这些文件同样按 14 天保留；`update.log`（更新日志）永远不删。
- 照片/合同页面用了目录缓存，「找有没有这张图」不再反复扫描 NAS 磁盘；上传/删除后立即刷新，手工拷进目录的最多 3 秒可见。
- 数据量继续增大时的**根本解法是把「整本台账」拆成按实体保存**（已排期的专项）：
  需要先做数据迁移与回滚方案、备份流程，**不会夹在功能改动里顺手做**。
  在此之前，保持每月备份即可。

## 12. 一键更新按钮点了没反应 / 提示没有 docker.sock

- **飞牛**：「一键更新」需要 compose 里挂了 `/var/run/docker.sock`（默认已挂）。
  提示「本机没有挂载 docker.sock」时，改用 `./一键拉取.sh`，或把挂载加回去后重建容器。
- **Windows 解压版**：直接点更新即可（先确认 Releases 里有比本机更新的包）。
- **不想开放这个能力**（安全考虑）：可以删掉 `docker-compose.yml` 里
  `- /var/run/docker.sock:/var/run/docker.sock` 这一行，然后不用软件内的更新入口，
  改为 `./一键拉取.sh` 或覆盖文件后 `./一键部署.sh` 升级。**详细三步见《部署说明.txt》第七节。**
- 更新前请先读第 1 条（版本没变）——很多「没反应」其实是加速站还在发旧镜像。

## 13. 出问题该给维护的人什么信息

一次给全，能省很多来回：

1. **当前版本号**（软件左下角，或 `VERSION.txt` 第一行）。
2. **你做了什么、期望什么、实际发生了什么**（越具体越好，例如「在报销单里传 8MB 的凭证，提示照片太大」）。
3. **界面上的提示原文**（截图最好）。
4. **`data/logs/` 里当天日期的日志文件最后 50 行**（升级问题再用 `设置 → 软件更新 → 查看更新日志`）。
5. 出问题的页面地址（浏览器地址栏那一段）。

> 再次提醒：**不要删 `data`**。绝大多数问题都能靠备份 + 日志定位，删数据只会让问题无法挽回。
