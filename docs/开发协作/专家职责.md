# 工地台账 · 专家职责与协作规范

> 整理日期：2026-09-18。适用于人类开发者、主智能体与受委派专家。
> 开发规则以[根开发规范](../../开发规范.md)为准；开始任务先读[AGENTS](../../AGENTS.md)与[文档索引](../README.md)。本文细化协作职责，不另设一套业务、安全或发布规则。

## 1. 使用原则

选专家是为了补足具体能力、并行完成独立工作或提供独立复核，不以人数、头衔或报告篇幅作为质量证明。

- 简单文案、局部样式和边界清楚的小修，由主负责人直接完成并按开发规范验证，不要求召集所有专家。
- 影响业务数据准确性、持久化、账务口径、权限边界，或复杂跨模块改动，必须安排独立复核；按实际风险选择有相应能力的复核者，不机械要求每类专家各来一位。普通只读展示的小改不因此强制多人处理。
- 一个专家可承担相邻职责，例如数据契约与 Excel 往返测试。**同一改动的实现者自查不能算独立复核**，改头衔也不能改变这一点。
- 只有用户已授权，或适用指令明确允许时，才启动子智能体；本表列出角色不等于授权无限派生、后台持续工作或启动额外任务。人数、模型与工作方式按可用能力和任务规模确定。
- 小任务通常直接执行；复杂任务先拆清依赖。能够独立推进且有明确交付边界的工作才并行，依赖前置结果的工作顺序推进。
- 专家不可用时，可由主负责人承担相同职责；需要独立复核的任务应争取另一位具备能力的开发者复核。暂时没有复核者，可先完成本地成果并注明“未独立复核”及影响，不把该验收项标为通过，也不因此虚称已经达到发布条件。

## 2. 角色与任务路由

以下标准名称和文件名已在本地专家目录核对。文件名用于在当前环境的专家目录中定位，不依赖某台机器的绝对路径；找不到时按职责选等效能力，不能假装已调用该专家。读取与本次任务相关的角色说明，不必每次加载全目录。

| 任务类型 / 调用时机 | 标准专家名称与本地文件名 | 本项目责任范围 | 交付与验收证据 | 禁止越界 |
|---|---|---|---|---|
| 跨模块依赖、存储/同步方案、新实体或结构重构 | **Software Architect**；`engineering-software-architect.toml` | 划定模块边界、依赖方向与兼容范围；比较保留现状/最小改进及确有必要的替代方案；识别迁移和回退条件 | 涉及文件、至少两种有实际差别的方案及代价、选型理由、关键不变量；重大决定按开发规范记录，需迁移时给演练结果 | 不因偏好重写技术栈，不以 DDD/微服务等名称代替问题分析，不自行改变账务口径 |
| 工资/出勤/发放/合同/保险计算、模型、Excel、备份恢复、批量操作 | **Data Engineer**；`engineering-data-engineer.toml` | 把已决策业务口径变成数据契约；核对字段、身份关联、跨年、零值/缺失值、舍入、重复导入、删除关联与恢复范围 | 最小合成样本、人工可核对的预期值、前后条数/金额/年份对照、适用的往返和边界测试；指出历史数据兼容影响 | 不替用户决定工资、税率和权限产品口径；不为适应实现而改预期值；不读写生产资料来凑样本，不擅自清重或迁移 |
| 页面/编辑弹窗/筛选/移动端/打印交互 | **Frontend Developer**；`engineering-frontend-developer.toml` | 沿用组件、主题与状态模式；处理真实操作路径、只读门禁、失败提示、防误关、键盘操作与布局 | 主要交互结果、桌面与手机视口尺寸及截图；打印改动给真实 PDF 与分页检查；未测浏览器/辅助技术明确标注 | 不用隐藏按钮代替服务端权限；不在页面重写账务计算；不以屏幕截图证明打印分页；不为视觉统一抹掉业务差异 |
| 登录、账户、成员、租户、API、上传下载、路径、敏感日志、依赖风险 | **Application Security Engineer**；`security-appsec-engineer.toml` | 检查信任边界、服务端授权、鉴权与读 body 顺序、隔离、输入限额、秘密和敏感字段；区分可利用缺陷与加固建议 | 具体入口与前提、影响、文件定位、无生产数据的复现或代码路径证据、修复后拒绝/允许两类测试 | 不擅自外网扫描、读取凭据或扩大权限；不把“内网工具”当免检理由，也不把泛化合规要求当成已确认业务需求 |
| 关键流程、修复回归、跨模块集成、浏览器与打印验证 | **Test Automation Engineer**；`testing-test-automation-engineer.toml` | 按风险分配纯函数/接口/集成/浏览器测试；造独立数据、验证成功与失败路径，维护扫描守卫自检 | 命令、环境、退出状态、失败日志/截图/PDF、针对缺陷的复现与修复后结果；说明未覆盖范围 | 不把所有测试堆进 E2E；不删断言、吞失败或反复重跑到绿来宣称修好；不使用生产台账作为自动化测试目录 |
| 页面变慢、数据量增加、重复计算、同步传输或内存瓶颈 | **Performance Benchmarker**；`testing-performance-benchmarker.toml` | 先定位成本，再测代表性规模；评估优化对行为、资源和维护成本的影响 | 同环境/同数据规模的前后结果、采样方式与次数、耗时/内存等相关指标、结果一致性对拍；只有复杂度分析时明确说未实测 | 不凭感觉报提升百分比，不只展示最佳一次，不为速度改舍入/排序/重复行等语义，不用压测冲击生产 |
| Node/pnpm、构建产物、CI、Docker/Windows 交付、一键更新 | **DevOps Automator**；`engineering-devops-automator.toml` | 核对依赖、质量门禁、同一提交构建与发布、模板/生效配置、更新就绪及回退 | 本地相关检查、构建指纹、脚本语法；若已授权实际发布，再给对应提交的 CI、镜像/附件与就绪结果；无法验证的环境说明原因 | 改 CI 不等于获准推送/发布；不放宽门禁求绿，不删除回退所需旧版本，不把本地成功宣称为远程成功 |
| 数据/权限/复杂跨模块改动的独立复核，或需要第二视角的风险改动 | **Code Reviewer**；`engineering-code-reviewer.toml` | 对最终差异检查正确性、兼容性、维护成本、风险与验证充分性；结合专项专家结论去重和质疑 | 按影响分级的发现、触发条件、源码定位、证据、建议；若未发现问题，写明审查范围和剩余限制 | 不要求纯个人风格调整，不为了“至少若干问题”虚构发现，不将实现者自测报告直接签作独立复核结论 |
| 功能说明、部署步骤、规范、报告索引、历史决策整理 | **Technical Writer**；`engineering-technical-writer.toml` | 对照现行代码/命令写可执行说明；区分现状、建议、已决策与历史；维护单一入口和引用 | 修改位置、与实现的对应关系、链接/路径检查、适用命令验证；无法执行的步骤标为未验证 | 不另造重复规则/待办清单，不把计划写成已落地，不为文档数字好看维护虚假的固定用例总数，不虚称完美 |

角色只提供工作方法。通用模板中“所有项目必须上云/软删除”“每项固定跑十遍”等要求，不自动成为本仓库规则；是否采用按任务收益、风险及[开发规范](../../开发规范.md)决定。动态库 API、工具用法和环境能力需按实际版本核实，不直接复制角色文件中的演示代码。

## 3. 主负责人与文件所有权

每个任务只有一个主负责人，对范围、接口协商、整合、最终验证与用户交付负责。子任务完成不代表整个任务完成。

1. **开始前盘点**：主负责人检查现有修改、相关规范、已决策事项和待办，确定预期行为与验收证据。先确认项目已有实现，不以“别的智能体写的”作为重构依据。
2. **派工时定界**：写清每位协作者负责的文件/模块、只读或可写、禁止触碰范围、前置依赖、返回格式。跨模块契约先明确输入、输出与失败语义。
3. **共享目录按文件分工**：告知“你不是唯一协作者”；不得回退、格式化或删除他人改动，不使用全仓还原。需要修改别人拥有的文件时先协调归属，由一个人合并该处修改。
4. **共享文件集中整合**：`package.json`、lockfile、模型/路由生成文件、规范索引、构建产物等易冲突文件由主负责人或明确指定的一位协作者维护。构建/生成/打包集中运行，避免覆盖中间结果。派工名单保存在本次任务记录，不在长期规范里维护人员花名册。
5. **等待不扩大范围**：被依赖结果未完成时，可做无依赖检查；不能猜接口实现，也不另开相同任务重复编辑。角色发现范围外问题，提供证据给主负责人，由主负责人决定是否本轮纳入或登记待办。
6. **合成数据与授权边界**：测试服务用隔离数据目录；读取用户业务资料应有当前任务的必要性与授权。删除、迁移、外发、发布等动作仍遵守用户授权和开发规范，不随派工自动扩张。
7. **整合后再判定**：主负责人审查所有差异、解决接口冲突，按最终文件状态跑规定检查。某子任务早先通过的结果不能覆盖后续相关改动。

只读复核者默认不改实现。发现缺陷后交给文件负责人修复；若复核者转为实现者，应记录角色变化，该补丁再交由未参与该实现的复核者检查，不能自批。

## 4. 输入、输出与独立复核

派工至少提供目标、授权范围、当前基线、文件所有权、相关口径、已知风险和验收方式。审查任务同时提供最终 diff 或明确比较范围，避免只看实现者的摘要。

交付至少包括：具体改动/发现、文件位置、行为影响、真实验证结果、残余风险或阻塞。没有文件改动的审查也应有检查范围与结论。

- **证据绑定对象**：记录提交 SHA；未提交工作区注明检查时间与文件范围。复核后若改动相关逻辑，重审受影响部分，不必机械重跑全部无关检查。
- **独立性可追溯**：记录实现者与复核者的角色/任务标识。独立复核者自己阅读差异与相关调用路径，并独立评估关键证据；不要求重复每一条慢测试，但必须说明引用了谁的结果、哪些由自己验证。
- **有范围才有结论**：“已检查跨台账拒绝路径”可以成立；“所有安全问题已经消除”不可以。静态检查、源码守卫、浏览器检查、真实 PDF、部署检查分别说明，不相互冒充。
- **未跑就是未验证**：环境缺失、没有授权、超出范围、工具失败分别写原因与影响；本地测试不等于 CI 通过，模拟结果不等于真实设备结果，测试全绿不等于没有未知缺陷。
- **按风险收敛**：验收门槛沿用开发规范 §9–10，不另行叠加全量检查。性能采样、稳定性复跑在有测量需要、失败或改动时进行，不为“专家流程”重复消耗。

## 5. 发现分级、处理与关闭

先确认是否真实问题，再给优先级；疑点可以登记“待核实”，不写成确定缺陷。每条发现写出触发条件、用户影响和证据，优先级不是由文件大小或专家资历决定。

| 级别 | 判据与例子 | 处理要求 |
|---|---|---|
| P0 紧急 | 已发生/正在发生的数据损坏、敏感泄露、可利用的严重越权，或核心服务大范围不可用 | 立即通知主负责人，阻止带该缺陷发布；在授权范围内先控制影响并保留证据，再修复和验证。不得擅自操作生产环境。 |
| P1 高 | 已复现的账务错误、保存丢失、跨册风险、关键路径无法使用、发布会绕过质量门禁 | 本次相关交付前修复并复核；确需暂缓须明确影响、缓解措施与有权用户的决策，不能称已修。 |
| P2 中 | 有明确触发条件的次要功能/体验问题、数据规模达到一定程度才出现的性能问题 | 按当前目标决定本轮修或登记后续，保留复现条件与验收标准。 |
| P3 建议 | 低影响维护优化、非阻塞文案或一致性建议 | 说明收益，不因审美偏好阻塞交付；可记录为无需调整或建议。 |

每条发现最终落为“已修并验证 / 已改待验证 / 待核实 / 待决策 / 延后处理 / 无需改”。“无需改”必须有反证、过时原因或已决策取舍；已接受取舍若出现新证据可以重开。不得只以“测试通过”或“专家说过”关闭业务口径争议。

修复关闭需关联修改位置、复现到修复后的验证、独立复核状态（适用时）；原报告末尾追加处理状态。未闭环项统一汇总到[文档索引](../README.md)，本文不再维护第二份待办清单。

## 6. 规则冲突与决策

- 遵守系统/平台等适用的上位指令；在项目约束内，以用户当前明确授权和决策为先。角色说明是专业方法来源，不能替代授权。
- 项目开发行为以根开发规范为唯一正文；AGENTS 摘要、本文、测试注释及历史报告出现矛盾时，核对实际行为、当前用户决策与保护目标，由主负责人修正文档和必要的测试。不能只选最宽松的一条，也不能把代码现状自动视为正确。
- 专家意见相反时，各自提供反例、证据与代价。主负责人处理普通实现取舍；工资口径、权限开放、磁盘格式/生产迁移等关键决策按已有授权推进，缺关键决策时集中向用户说明选项及影响。继续完成不依赖该决策的工作。
- 重大结构改变需要比较可行选项并留下选择理由；一般小修不要求另建 ADR。规范不足时优先补保护目标、适用条件、验证方式，不从一次事故推导永久禁止某项技术。
- 不承诺“完美规范”“零缺陷”或“全面无风险”。长期可用依靠明确职责、可验证结果与持续修正规则。

## 7. 可复制模板

### 派工

```text
目标：修复/审查什么；用户期望行为是什么。
角色与模式：标准角色名；实现 / 只读复核。
授权与所有权：可改文件/模块；禁止触碰范围；禁止生产写入/发布等边界。
协作：你不是唯一协作者；保留他人修改；跨所有权文件先协调。
输入与依赖：基线 SHA 或工作区范围、相关规则/报告、已有复现与前置结果。
验收：需保持的不变量、测试/浏览器/PDF等证据及本轮验证分工。
返回：改动/发现、文件位置、验证命令与结果、未验证项、风险与待决策事项。
```

### 实现交付

```text
结果与范围：解决的问题、行为变化、涉及文件。
验证对象：SHA 或工作区时间/范围。
证据：实际命令、环境、退出状态；截图/PDF/日志位置（脱敏）。
独立复核：复核者与结论；尚未完成则明确标注。
未完成/未验证：原因、用户影响、下一步；无则写无。
```

### 审查发现

```text
编号 / 级别 / 状态：
位置与触发条件：
预期、实际与用户影响：
证据与复现：
建议及代价：
修复负责人 / 验收方式 / 关闭证据：
```

### 主负责人最终交付

```text
交付物与使用方式：
已验证的范围和结果：
独立复核状态：
剩余问题/已接受取舍与索引链接：
发布状态：仅本地修改 / 已提交 / 已推送 / 已部署（只写实际完成的阶段）。
```
