## 四、数据模型与存储

- **单一数据根**：`DATA_DIR`（Docker 里 `/data`）。目录：`books/<bookId>/{ledger.json,audit.json,book.json}`、
  `accounts/accounts.json`、`photos/<bookId>/<分类>/`、`backups/`、`logs/`、`templates/`。
- **台账形状**：`src/lib/types.ts` 的 `LedgerState`（人员 / 考勤 / 发放 / 合同 / 合同明细 / 报销 / 保险单 / 被保人 /
  年度 / 界面风格），带 `schemaVersion`（当前 2），**整本一个 JSON**。
- **多台账隔离**：`withTenant(request, fn, need)` → `runWithBook(bookId)`（AsyncLocalStorage），
  影像按 `<photos>/<bookId>/<分类>/` 分目录（读路径只读回落历史公共目录）。
- **写安全**：CAS 版本号统一走 `ledgerRevisionValue()`（空台账哨兵 `""`）；写入串行队列 + 随机临时名原子写；
  坏文件判 `unreadable` 并拒绝写入（不做「当空覆盖」）。
- **权限**：`src/lib/perms.ts` 的 `PERM_TABLE` 是**唯一来源**（`PermId`/`NeedId` 由它推导），
  页面导航 `NAV_PERM`、预设 `PRESETS`、服务端 `withTenant(..., need)` 全部从它派生；`tests/perms.test.ts` 扫全库兜底。

## 五、请求与数据流

```
页面(routes) ── Zusatnd store（客户端权威）──┐
                                          ├─ nas-sync：PUT /api/ledger（If-Match + CAS）→ books/<id>/ledger.json
文件上传/导出 ─ /api/photo、/api/doc、/api/file/$kind ─ assets.server → photos/<bookId>/<分类>/
影像扫描/归入 ─ /api/photo-scan、/api/photo-adopt
操作记录      ─ /api/audit（POST 追加/PUT 改/DELETE 删，admin 之外只读）
账户与台账册   ─ /api/auth（setup/login/verify/useBook/createBook/renameBook/deleteBook/用户与成员 CRUD）
更新          ─ /api/update（GET 检查 / POST 触发 / ?status=1 轮询）、/api/update-log、/api/images
其它          ─ /api/health、/api/version、/api/year、/api/backup
```

API 路由清单（18 个 + `file/$kind`）：`audit`、`auth`、`backup`、`doc`、`file/$kind`、`health`、`images`、
`ledger`、`photo`、`photo-adopt`、`photo-file`、`photo-flags`、`photo-scan`、`update`、`update-log`、`version`、`year`。
