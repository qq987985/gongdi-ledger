# 查询、班组打印与月表复核 · 2026-11-14

基线：`983c863 / 1.9.2`。处理版本：1.9.3。用户要求复查最近的查询功能；本轮重新读取实现并寻找反例，未沿用上一轮“通过”结论。全部浏览器、接口、影像和导入试验均用临时合成 DATA_DIR，未读写生产 `data/`。

## 发现与处理状态

### 1. 同册人数变化丢掉未保存月表 · 已修复

原因：MonthTable 的 key 包含 `people.length`，同册增加或减少人员会重建编辑器。

- 旧构建真实复现：月表本地输入 21.5 天，服务器增加一个无关人员后拉取，界面恢复为 20.5 天，测试失败。
- key 只保留年月和台账身份代际；源快照变化时，仅整表仍等于上一份源快照才接纳新数据。存在本地修改时完整保留，不按姓名或索引猜测合并。
- 实测同册增人、减人保留 21.5；保存后再次刷新，未编辑的月表正确接纳服务器的 20.5；挂起拉取时编辑、拉取失败后的打印恢复及切换空册仍通过。

### 2. 真实分组名称撞「全部」哨兵，混入他组 · 已修复

原因：真实班组名 `__all__` 与 `ALL_BUCKETS` 使用相同字符串。独立纯函数反例中，本应只计甲的已发 100，实际混入乙变成 140。

- `groupBuckets` 为保留名称及转义前缀生成唯一选项键；`inBucket` 解码键后比较原始字段，普通值和空值保持兼容。
- 查找人数、人员筛选、打印标题、保险队长、待发放生成等消费者同步接入原值还原。编码仅留在筛选状态，不能写入业务字段；React key 直接用唯一选项键。
- 验证真实 `__all__`、`__empty__`、多层 `__bucket__:` 前缀及空值互不混合；查询、月表、人员名单、发放明细均按本组筛选并打印原名。
- 真实点击「按应发生成待发放」，服务端保存的 source 为原始 `__all__`，没有内部编码；特殊班组已发为 100，未混入另一人的 40。

### 3. 小数工天、小时累计出现长浮点尾数 · 已修复

原因：直接二进制相加，0.1 + 0.2 展示为 0.30000000000000004，且可能挤出打印窄列。

- 在 `num.ts` 新增 `sumQuantity`，以有限 Number 的十进制表示对齐小数位求和，最后返回 Number；不固定截两位或限制有效位，不修改原始记录。返回结果仍遵守 JavaScript Number 的精度和范围。
- 查询每人每月、月小计和区间合计、月表工天、班组打印及年度工天/小时采用同一实现。工资计算、金额舍入和已发口径保持原样。
- 单测覆盖 0.1 + 0.2、1000 次累计、合法长小数、正负指数、极大数抵消、极小数和负零；真实页面和 PDF 显示 0.3，年度与查询一致。

### 4. 通用手机检查探针的误报与漏判 · 已修复

- 原探针测横向滚动时把 y 重置为 0，导致“滚到底检查”实际回到首屏；现保留原滚动位置。
- 首屏被固定底栏暂时覆盖的按钮，实际滚到按钮后重新做命中测试；滚动后仍不可达才报问题。禁用按钮不当作可操作入口；命中祖先不当作命中按钮。
- 候选全部验证，不能提前按同名/同样式去重或截断；仅限制最终问题文本展示。问题非空时脚本以非 0 退出。
- 内置真实 Chrome 自检：可滚动恢复、固定永久遮挡、滚动位置保持、两个同名按钮部分不可达、pointer-events:none。独立复核另外验证前六个可恢复、第七个永久遮挡，正确检出第七个。
