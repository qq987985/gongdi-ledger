## 二、接口与权限（8 项，均已在真机复现）

1. **导出页「总台账」必 404**：客户端请求 `/api/file/ledger-export`，服务端只实现 `export`。
   → 服务端加 `KIND_ALIAS`、客户端改回 `export`；新增守卫测试盯住"客户端 kind 服务端必须认识"。
2. **`createUser` 忽略 `perms`**：传 `perms:"attendance.view"` 实际得到"只读"预设 14 项，能读全量台账、能导出人员名单。
   → 按 `perms` 白名单精确分配。
3. **自我提权**：只有 `members.manage` 的成员 `addMember` 自己 `perms="*"` → 提权成功。
   → 拒绝改自己的权限；普通成员不能授予自己没有的权限。
4. **损坏的操作记录被覆盖**：文件损坏时 `POST /api/audit` 用空列表"读—改—写"，实测 97 条 → 1 条。
   → 新增 `auditUnreadable()`，损坏时拒绝写入（503），与 PUT/DELETE 口径一致。
5. **`/api/year` NaN 写坏台账**：`Number("abc")` 的 NaN 绕过 `y < 2000 || y > 2100`，`year` 变 `null`、`years` 里塞 `null`。
   → 抽出 `isValidYear()`（整数 + 2000–2100）并加测试。
6. **非 JSON body → 500**：`PUT /api/ledger`、`POST/DELETE… /api/audit`、`/api/auth`、`/api/year`、`/api/photo`、`/api/doc` 共 7 处；
   未登录也能打出 500。→ 统一 try/catch 返回 400。
7. **超长文件名 → 500**：≥255 字节时 `rename` ENAMETOOLONG。→ 上传前限长（照片 120 / 文件 180 字节）返回 400。
8. **伪造 Content-Length 挂住连接**：声明 60MB 只发 2 字节 → 永不回包。→ 启动器加 52MB 上限，声明超限立刻 413。

另外补齐可观测性：未捕获异常 / 未处理的 Promise 拒绝现在也写 `data/logs/YYYY-MM-DD.log`（原来只有 stdout）。

## 三、Excel 往返（16 项）

数据错：整本/考勤导入年份识别不到标题（旧年备份落到今年）；重复导入整本使发放/报销翻倍；
在保人员被写成日期"在保"（二次导出变"已结束"）；带格式数值（`1,200`/`¥300`/`300元`/`22天`）被清成 0；
「总计」行被当成真数据；报销 0 值被重算、数量 0 被改成 1；合同明细空日期被填 `YYYY-01-01`；
未记税率的开票明细凭空生成不含税金额。
丢字段：合同只留管理表时报量/已付合计丢、扫描件/有无合同/无合同原因丢、保险合同文件丢、被保人备注丢、
只有备注的考勤行导出即丢、明细 sheet 排前面时明细整批丢、考勤"增加"模式按姓名整人跳过。

修法要点：标题年份识别、内容键去重（`mergePayments/mergeExpenses`）、派生表统一排除（`isDerivedSheet`）、
容错数值解析（`parseNumber`）、合计行统一过滤（`isTotalRow`）、合同两趟解析、以及把"有值（含 0）"与"整列缺失"区分开。
