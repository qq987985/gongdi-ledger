## 三、失败项与缺陷（只记录，未修改代码）

### D1【高】报销编辑弹窗不随 draft 重置：点「新增报销」会覆盖正在编辑的那条记录（数据丢失）

- **对应项**：E11（失败）
- **复现步骤**：① 新增报销「覆盖测试A / 金额 11」并保存（保存后弹窗保持打开，标题变为记录名）；② 弹窗仍开着时点页面右上角「新增报销」；③ 弹窗标题变为「新增报销」，但表单里**项目仍是「覆盖测试A」、金额仍是 11**（未重置）；④ 改成「覆盖测试B / 22」保存。
- **实测**：`覆盖测试A` 保存后列表 = [..., "覆盖测试A"]；最终列表 = [..., "覆盖测试B"]，**「覆盖测试A」整条消失**（被同 id 覆盖）。
- **代码定位**：`src/components/expense-editor.tsx`（`ExpenseEditor`）用 `useState(() => ({ ...draft, ... }))` 初始化本地副本，**没有随 `draft` 变化的同步 effect**；对照 `src/routes/payments.tsx` 的 `PaymentEditor`，它有 `useEffect(() => setC({ ...draft }), [draft.id])`，所以**发放编辑弹窗不存在这个问题**（同场景实测不丢记录）。
- **影响**：用户「先看一条旧的、再点新增」时会静默丢掉上一条记录，且没有任何提示。
- **对照验证（Y15 通过）**：**同样的操作在「发放记录」页不会丢数据** —— 新增「弹窗对照A/11」后不关弹窗直接点「新增发放」，标题变为「新增发放」且收款人/金额输入框都清空，保存后 A、B 两条都在。可见根因就是 ExpenseEditor 缺 `[draft.id]` 同步 effect，修法可照抄 `src/routes/payments.tsx` 的 PaymentEditor。
- **证据**：`/tmp/gd-tB/shot/E11-stale-form.png`；对照 `/tmp/gd-tB/shot/Y15-pay-editor-reset.png`

### D2【中】人员编辑弹窗同样不重置：「新增人员」会沿用上一条档案的字段

- **对应项**：P19（失败）
- **复现步骤**：① 点「张三」的「编辑」（姓名输入框 = 张三）；② 弹窗开着时点页面「新增人员」；③ 标题变为「新增人员」，但**姓名输入框仍显示「张三」**；④ 改成「重置校验甲 / 测试班」保存。
- **实测**：新增出来的「重置校验甲」**带上了张三的电话 13800000001**（身份证号、银行卡号、开户行等同理会一起带过去），人员数 9→10。

- **证据**：`/tmp/gd-tB/shot/P19-stale-form.png`；对照项 Y15（发放页同场景正确重置）通过

### D3【低】发放「导出 → 导入」不幂等：收款人为空的记录会多出一条重复流水

- **对应项**：Y14（失败）
- **复现步骤**：導出全部发放 → 用「导入发放」（增加模式）把同一份文件导回。
- **实测**：预览「payment-export.xlsx · **7 条 · 跳过 6 条重复**」，toast「已追加 **1** 条发放记录，跳过 6 条重复」，条数 7→8；重复出现的「钱七」记录数 = 2（导出前 receiver 为空的记录数 = 1）。
- **原因**：`src/lib/excel/payments.ts` 的 `rowToPayment` 里 `const receiver = pick(row, ["收款人"]) || owner;` 会把空收款人回填成 owner；而去重键 `src/lib/excel/common.ts` 的 `paymentKey`（`[owner, date, amount, receiver]`）含 `receiver` —— 落盘记录 receiver 为空（""），导出件解析后 receiver=owner，两者键不同，于是重复导入。（注意：这与「日期没补零导致键不等」是**两个不同的根因**，本次实测的重复来自 receiver 回填。）
- **影响**：每次「导出再导入」都会把「收款人为空」的历史记录复制一份，金额/笔数被放大。
- **证据**：`/tmp/gd-tB/payment-export.xlsx`（第 7、8 行同一条钱七记录）

### D4【低】空收款人被标成「代收」，与汇总「其中代发」口径不一致

- **对应项**：G04（失败）
- **复现步骤**：搜索「钱七」（该笔 receiver 字段为空）→ 看列表徽标、「其中代发」统计、打印明细里该行的收款人标注。
- **实测**：列表徽标 = **代收**；打印明细写「钱七**（代收）**」；但同一筛选的汇总行是「其中代发 **¥0.00（0 笔）**」，面板也没有代发标注。
- **原因**：列表徽标与打印件用裸比较 `p.owner !== p.receiver`（`src/routes/payments.tsx` 列表「代收」徽标、`src/components/payment-sheets.tsx` 明细「（代收）」），而统计口径用 `receiverOf()`（`src/lib/payments-stats.ts`，空 = 同实际收款人）。
- **影响**：旧数据/导入数据的空收款人会被显示成「别人代领」，与统计口径互相打脸。
- **证据**：`/tmp/gd-tB/shot/G04-receiver-empty.png`

### D5【低】「没设加班规则」在月表/人员表显示成「不计加班」，与顶部警示口径不一致

- **对应项**：A14（失败）
- **实测**：6 月考勤顶部警示「有 **2** 人还没在人员表设加班规则，加班费会算成 0」，但同一页「加班规则（人员表）」列里王五、钱七显示的是「**不计加班**」；人员页同一列也显示「不计加班」（两处都取 `parseOtRule().label`，而 `src/lib/wage.ts` 的 `parseOtRule` 对空规则返回的 label 固定是「不计加班」）。
- **影响**：用户无法从表格区分「没设（视为不计加班）」与「明确选了不计加班」，与警示文案冲突；属显示口径问题，不影响计算。
- **证据**：`/tmp/gd-tB/shot/A14-otrule-label.png`
