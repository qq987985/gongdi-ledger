# 结构重构报告（模块化 / 可拓展 / 低耦合专项）· 2026-09-14

> 背景：用户在 1.7.17 发布后提出「模块化、可拓展、低耦合这三条做到了吗」，上一轮评估结论是
> **部分做到、但有三处明显失分**（循环依赖、两个上帝文件、无关功能耦合）。
> 本报告记录本轮重构的评估依据、拆法与验证结果。基线：1.7.17（提交前工作区）。
> 范围声明：**只做搬代码与解依赖，不改任何行为**；实体级存储（未闭环清单 A）仍是专项，不在本轮。

## 一、重构前评估（三条标准逐条打分）

| 标准 | 结论 | 依据 |
|---|---|---|
| 模块化 | ⚠️ 部分做到 | 页面/路由已按模块分；但 `excel.ts` 1320 行装了 7 个实体的导入导出，`nas-fs.server.ts` 1184 行装了路径+影像+台账+审计 |
| 可拓展 | ⚠️ 部分做到 | 加一个新实体要在一个 1300 行文件里找位置；影像类型与台账存储焊死（见下） |
| 低耦合 | ❌ 有三处失分 | ① `dates.ts ↔ wage.ts` 循环依赖；② 照片组件为拿 `nasEnabled()` 要 import 整个同步引擎 `nas-sync.ts`；③ 影像归入 `adoptLegacyAssets()` 内部自己去读台账，影像层与台账存储互相依赖 |

## 二、拆法（A/B/C 三项）

### A. 解环 + NAS 开关抽离

- **`hasWork`（出勤判断）从 `wage.ts` 移到新模块 `src/lib/work.ts`**：`dates.ts` 需要它做月份状态判断，
  `wage.ts` 需要 `dates.ts` 的日期解析 —— 把共同依赖下沉到 `work.ts` 后环消失（dates → work，wage → work）。
  调用方（`dates.ts`/`excel.ts`/`query.tsx`/`attendance.tsx`/`api/file/$kind.ts`）全部改从 `work` 导入。
- **`nasEnabled` 从 `nas-sync.ts` 移到新模块 `src/lib/nas-flag.ts`**：照片/文档组件、设置页、外壳
  只需要「NAS 是否可用」这一个布尔值，不再依赖同步引擎本体（探测/推送/拉取仍在 `nas-sync.ts`）。

### B. `excel.ts` 按实体拆分（barrel 兼容）

`src/lib/excel.ts`（1320 行）→ `src/lib/excel/` 目录：

| 模块 | 内容 |
|---|---|
| `common.ts` | 共享层：容错数值解析、行/表读取、日期规整、文件名安全、去重合并键、模板 sheet 构件 |
| `people.ts` / `attendance.ts` / `payments.ts` / `expenses.ts` | 各实体的 rowTo*/parse*Sheet/*TemplateWb/*SheetAoa/build*Workbook |
| `insurance.ts` | 保险人员模板与解析 |
| `contracts.ts` | 合同解析（含两趟解析、税率/含税模式）、合同模板与导出 |
| `full.ts` | 整本导入解析 + 整本导出（依赖前五个实体模块） |

原 `excel.ts` 只剩 `export * from "./excel/..."`，**调用方零改动**（含 70 个往返对拍用例）。
依赖规则：`common` 不依赖实体模块；实体模块只依赖 `common` + wage/dates/idcard/types；
只有 `full.ts` 可以依赖实体模块（方向单向，无环）。

### C. `nas-fs.server.ts` 拆成三层

| 模块 | 职责 |
|---|---|
| `paths.server.ts` | 数据目录、台账上下文（AsyncLocalStorage）、目录初始化/迁移/模板种子、`listDirSafe`、`atomicWriteFile` |
| `assets.server.ts` | 照片与文档的查找目录链（本台账优先、历史目录只读回落）、写入/删除/扫描/归入 |
| `nas-fs.server.ts` | 只留台账（CAS + 写队列）、审计（坏文件保护 + 串行追加）、Excel 备份、台账册、版本号 |

依赖方向单向：`paths ← assets ← nas-fs`。

**关键签名变更**：`adoptLegacyAssets(led)` 不再内部 `readLedger()` —— 由调用方
（`api/photo-adopt.ts`，在台账上下文内）先读出台账、判不可读后传入；影像层从此不依赖台账存储。
`readLedger()` 里「合同扫描件补名」需要的 `reconcileContractScans` 从 assets 导入（台账 → 影像的单向调用）。

调用方同步改导入：`persistOn/dataDir/runWithBook` → `paths.server`；照片/文档接口（photo、photo-file、
photo-flags、photo-scan、doc、photo-adopt）→ `assets.server`；accounts.server / update.server 同步。
