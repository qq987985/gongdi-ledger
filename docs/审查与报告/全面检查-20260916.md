## 二、确认并修复的问题（3 项，均已修 → 1.8.0）

### 1. 照片保存「先删旧、后 rename」，崩溃窗口内两头空（小）

- **位置**：`src/lib/assets.server.ts` `savePhoto()`。
- **问题**：原顺序是「写临时文件 → 删旧照片 → rename 新照片就位」。若 rename 失败（磁盘满、权限瞬时变化），旧照片已删、新照片还是隐藏临时名并被 catch 清掉——这张照片就丢了。这正是 1.7.17 在 `saveDoc` 上修过的同一类问题（未闭环清单第 9 条），照片路径当时没有对齐。
- **修复**：改为「写临时文件 → rename 新文件就位 → 再删旧文件」；清旧失败只记日志（留下一份旧副本，不影响新照片）。公共回落目录仍然只读不动。
- **守卫**：`tests/api-guards.test.ts` 新增「savePhoto 必须先 rename 就位再清旧」源码守卫。

### 2. 整本导出「全部年份」范围下，纯备注月份的考勤行导出即丢（小）

- **位置**：`src/routes/api/file/$kind.ts` `monthsFromAttendance()`。
- **问题**：「全部」范围导出时，月份 sheet 清单由 `monthsFromAttendance` 决定，它只认 `hasWork`（工天/加班/补助/扣款）；而 `buildFullWorkbook` 的行过滤用 `hasAttContent`（**备注也算有内容**，1.7.13 为「工伤休息」这类行专门修的）。两边口径不一致：若某个月所有人的考勤都只有备注没有工天（如整月停工养伤），该月不会生成 sheet，这些行在导出文件里凭空消失，再导入即丢失。
- **修复**：`monthsFromAttendance` 改为与 `hasAttContent` 同口径（`!hasWork(a) && !remark.trim()` 才跳过）。
- **守卫**：`tests/api-guards.test.ts` 新增「导出月份识别含备注」口径守卫。

### 3. 启动器请求级 500 只进 stdout，不落 data/logs（小）

- **位置**：`scripts/app-server-index.mjs` 请求处理的最外层 catch。
- **问题**：1.7.13 已让 `uncaughtException` / `unhandledRejection` 落 `data/logs/YYYY-MM-DD.log`，但被请求处理器**接住**的异常（更常见的那一类 500）只 `console.error`——NAS 上按日期翻 `data/logs` 依然什么都看不到，与 D 项可观测性的目标有缺口。
- **修复**：catch 里改用 `logLine("error", "请求处理失败", …)`（stdout + 落盘，自带 url/method/stack）。
- **守卫**：`tests/api-guards.test.ts` 新增「请求级 500 必须落盘」守卫。

## 三、观察记录（可接受取舍，本轮未改）

1. **`ensureDirs` 就绪缓存是单槽（`ensuredFor`）**：多台账并发请求会互相把对方的键顶掉，导致重复 mkdir（纯性能，不影响正确性；1.7.17 已把每台账一次的降载做到位，并发翻台并不高频）。
2. **会话令牌比较非 timing-safe**（`resolveTenant` 里 `token === expected`）：令牌本身是随机会话盐派生的 256 位值，内网部署下时序攻击不可行；改密码/停用会刷新盐使旧令牌全部失效，口径正确。
3. **`/api/auth` 的 `verify` 操作只凭 cookie 里的用户 id 做密码校验**（不验会话令牌）：知道用户 id 即可尝试密码——有 5 次/5 分钟限速兜底，且该接口不返回任何敏感数据，属可接受。

- **台账同步三条硬约束**（版本号同源 / pullDepth 禁推 / seed 仅首启）：`nas-sync.ts` 与 `nas-fs.server.ts` 逐条核对，均保持。
- **写路径原子性**：台账 / 账户库 / 审计 / 文档 / 照片全部临时文件 + rename，且写队列串行；坏文件一律拒绝覆盖（台账 / 账户库 / 审计三处口径一致）。
- **更新链路**：镜像版本核对、按 sha 拉取、更新容器存活检查、回滚顺序、旧镜像清理、`.gondi-next.json` 走 DATA_DIR——1.7.10 的真因（脚本语法）有 `new Function` 解析守卫钉住。
- **Excel 往返**：70 个对拍用例覆盖历史上反复出问题的全部点位；本轮新增的口径问题（第 2 项）不在既有对拍路径上（对拍走客户端 `buildFullWorkbook` 默认 12 个月清单，不走路由层 `monthsFromAttendance`），已用守卫测试补上。
