## 1. A 级：确认缺陷（有证据，建议本轮修）

### A1【数据·跨册写错】租户解析静默回落 —— 指定册子不可访问时读写都落到「第一本可访问册子」
- 证据：`src/lib/accounts.server.ts:305` `const book = mine.find((b) => b.id === bookId) || mine[0] || null;`
  实测（Backend Architect）：cookie 指 `copy1`，PUT 结果写进了 `books/default/ledger.json`；界面仍显示旧册名。 **[父会话已复核]**
- 影响：成员被移出某册 / 册子被删后，客户端仍带旧 `gongdi_b`，**整本快照会写进另一本册子**（跨册数据污染，最难恢复的一类）。
- 最小修法：显式请求的 `bookId` 存在但不可访问 → 返回 403/404（不回落）；只有「未指定」时才回落第一本；客户端遇 404 重新拉册子列表并提示。

### A2【数据·假冲突诱导覆盖】PUT 响应头的版本号用**请求体**算，GET/CAS 用**服务端文件视图**
- 证据：`src/routes/api/ledger.ts:149` `response.headers.set("X-Ledger-Revision", ledgerRevisionValue(body))`；
  GET 与 CAS 走 `src/lib/nas-fs.server.ts:67/92`（CAS 比对 `ledgerRevisionValue(cur)`），而 `readLedger()` 会先 `reconcileContractScans()`
  就地补 `scanFileName`（只补内存视图、不回写）。于是「客户端存下的基准」≠「服务端文件的 hash」。 **[父会话已复核]**
- 影响：客户端拿 PUT 返回的头当基准（`nas-sync.ts:284/295`），**下一次保存必然 409**「已被其他设备修改」，
  弹窗诱导用户点「以本机覆盖」→ 真丢别人的改动。违背 AGENTS.md 硬约束 #1（版本号口径必须同源）。
- 最小修法：PUT 成功后用**服务端写入后的视图**（同一份 `readLedger()` 口径）算头返回；加一条端到端测试：连续两次保存不产生 409。

### A3【安全·凭据链】台账里的 `accessHash` 被抬成管理员口令 hash
- 证据：`accounts.server.ts:232-244` `adminFromOldLedger()` 直接 `{ role: "admin", hash: raw.accessHash }`；
  `:100-103` 的 `verifyPassword` 接受旧的 `sha256("gongdi-ledger::"+pwd)` 比对；`accessHash` 还留在 `ledger-schema.server.ts:51` 允许的字段里（`people.view` 就能读到）。 **[父会话已复核]**
- 影响：**能读到台账的人（或任何拿到 ledger.json 的路径）可以直接登录成管理员**。属「唯一能拿管理员」的凭据链（CWE-916/759/522）。
- 最小修法：① schema 去掉 `accessHash`（写入时丢弃并记一条日志）；② 首启不再由它引导管理员，改成要求显式创建（或只在交互式首次设置时用一次性口令）。

### A4【安全·未认证 DoS】4 个写接口在读 body **之后**才鉴权
- 证据：`api/backup.ts:14`（读）↔ `:25`（withTenant）；`api/doc.ts:71` ↔ `:88`；`api/photo.ts:40` ↔ `:56`；`api/ledger.ts:104` ↔ `:135`。 **[父会话已复核]**
  Backend Architect 实测：未登录发 40MB body → 先吃满内存再回 401。CWE-770/400。
- 最小修法：把这 4 处的 `withTenant` 提到读 body 之前（每处 2 行）。

### A5【安全·审计不可否认性】审计可被批量删除且**不留痕**，影像删除服务端零审计
- 证据：`api/audit.ts:84-95` DELETE 直接 `writeAudit(list.filter(...))`（没有先 `appendAudit` 记「删了哪几条/谁删的」）；
  `api/doc.ts:97-111`、`api/photo.ts:65-82` 删除不写审计。 **[父会话已复核（audit.ts 部分）]**
- 影响：删证件照/删审计记录事后查不出来 —— 对「台账要能对账追责」的场景是硬伤。
- 最小修法：删除前先 `appendAudit({ 模块:"审计", 操作:"删除操作记录", 内容:ids.join(",") })`；doc/photo 删除补审计。

### A6【数据·口径】姓名 trim 不统一 → 年度表把一个人拆成两行、出勤可能归零
- 证据（Code Reviewer 实测）：人员姓名从不 trim（`people.tsx:489`）、发放 owner 保存时 trim（`payments.tsx:480`）、
  Excel 导入 trim（`excel/common.ts:117`），而 `attendance-summary.ts:144/172/215` 只在比较**一侧** trim。
- 影响：带空格的历史数据 → 年度表同一人两行（已发对不上）、整年出勤静默归零（应发 KPI=0）。
- 最小修法：入库存档前统一 trim（人员姓名、考勤姓名），比较两侧都 trim；加一条带空格姓名的回归用例。

### A7【数据·金额】发放/合同金额入库不做 `round2`
- 证据：`payments.tsx:492`、`excel/payments.ts:27`、`contracts.ts:124`（报销已 round2）。
  实测：亚分金额下打印件出现「已发 0.01 + 待发 0.01 = 0.01」「明细小计 0.02 ≠ 表尾 0.01」。
- 最小修法：入库前 `round2`（与报销/工资同口径），补一条断言。

### A8【交付·发版完整性】CI 第四道闸恒真 + 发布用入库的 `app/` 构建 → 忘记重建会全绿发版
- 证据：`.github/workflows/check.yml:51-66` 在 `pnpm run build` 之后才查 `app/VERSION.txt`（build 必写）与文件存在性（build 必满足），
  唯一的字节比对判据在 `76b8099` 被从 `exit 1` 降级成 `::warning`；而 `.github/workflows/docker.yml:31-38` + `Dockerfile:9` 直接用**提交进仓库的 `app/`** 构建并推 `latest`（docker job 不跑任何闸门）。
- 影响：源码改了忘了 `pnpm build` → 闸门全绿、镜像/Release 发出去的是**旧代码**而版本号已是新的（用户端更新后「版本变了行为没变」，极难定位）。
- 最小修法（须在 GitHub 网页改 workflow）：docker job 在构建前自己跑一次 `pnpm install --frozen-lockfile && pnpm build`，并把 `app/` 漂移检查改回硬失败（`exit 1`）。

### A9【可观测性】`SLOW_MS` 未设置时解析成 0 → 每个请求都写一条「慢请求」
- 证据：`scripts/app-server-index.mjs:165-167` 用 `n >= 0` 判定（`Number("")`=0 通过）→ 启动行自报 `slowMs:0`；
  实测 46ms 的 `/api/health` 也被记 warn。文档（FAQ:147、架构方案:260）写的是 2000ms。两位专家独立确认。 **[父会话确认代码]**
- 影响：`data/logs` 被请求流水灌满（8MB ≈ 6 万行）、撞上限后启动器「当天停写」、每请求多一次同步落盘。
- 最小修法：改成 `n > 0`（一行）。

### A10【前端·权限】查询页对只读账号仍开着编辑入口
- 证据：`query.tsx:384` 只判 `query.view`；`:537-539` 的 `PhotoSlot` 没有 `readOnly` 入参；`:622` 的 `DocActions` 未传 `readOnly` →
  能点，服务端 `api/photo.ts:57/86`、`api/doc.ts:19-24` 必 403。守卫 `tests/readonly-guards.test.ts:32-40` 的 `EDIT_PAGES` 不含 `query.tsx`（**假绿**）。
- 最小修法：query 页传 `readOnly`、把 query.tsx 加进守卫扫描清单。

### A11【前端·失败可见性】7 处写操作没有 catch → 失败时界面毫无反应
- 证据：`members-card.tsx:73/89/125`、`insurance.tsx:589`（>50MB 的 413 文案永远看不到）、
  `doc-actions.tsx:374/409`（查询/报销/合同/保险/考勤影像共用）、`attendance.tsx:629`。
- 最小修法：统一 `catch (e) { toast.error(服务端原文 || 通用文案) }`，并加源码守卫（同 `accounts-card.tsx:212-224` 的写法）。

## 2. B 级：风险/隐患（有推理链或部分证据）

- **B1【可观测性·两套实现】** 日志上限：`src/lib/log.server.ts:42/152/217-252` 超限**滚动** `.log.N`；生产启动器 `app-server-index.mjs:226/240-247` 超限**停写当天文件**（`:228` 字节计数只在当天首写 stat 一次），而 `AGENTS.md:85-86`、`开发规范.md:337`、使用说明书:163 都写「1.8.4 起不再停写」。实测 `LOG_MAX_MB=0.001` + 12 次请求：启动器那路只入盘 7 条、其余丢弃。**影响：线上慢请求/5xx 到 8MB 后当天不再留证**。修法：启动器直接用 `src/lib/log.server.ts` 的同一实现（或抽出共享模块，禁止两份复刻）。
- **B2【前端·静默失败】** `nas-sync.ts:317-324` 只在首次失败弹提示（`pushFailed` 锁存），之后全静默；401（会话失效，`accounts.server.ts:755`）被写成「请检查网络」；全库没有「未同步」状态指示 → 典型「以为存上了其实没落盘」。
- **B3【前端·只读误报】** 只读账号切年份就会置 `dirty`（`year-switcher.tsx:51/70 → store.ts:305 → nas-sync.ts:386-392`）→ 弹「没有保存整本台账的权限，改动只保留在本机」，且 `dirty` 从此永久为真，之后新建/切台账都被问「本机改动会被覆盖」。
- **B4【交付·更新无就绪校验】** `src/lib/update/updater-script.ts:63-73/88`：`start` 返回 200 就立刻删老容器、删旧镜像并记「更新成功」；`apply.ts:152` 探针只等 2s 而脚本 2.5s 才开工；Dockerfile/compose 无 `HEALTHCHECK` → **新容器起不来也回不去**（回滚只覆盖「根本没起来」）。
- **B5【交付·PID 1】** `Dockerfile:13` 的 PID 1 是 `sh` 不是 node，实测 `docker stop` 后 node 仍跑 200 直到 SIGKILL → 与 1.7.x 花大力气做的原子写/优雅退出不匹配（丢在飞保存）。一行 `exec` 可修。
- **B6【交付·Windows 启动器】** `win/启动.bat:3` 的 `cd /d "%~dp0.."` 是为 `win/` 子目录写的，而 `win/pack.sh:19-20` 把它放到 zip 根；`apply.ts:237/240` 更新后恰恰用 `start "" "%~dp0启动.bat"` 启动它 → **在线更新后服务不会自己回来**（需 Windows 真机复核一次）。
- **B7【数据·审计跨册】** `nas-fs.server.ts:140/147-173` 的全局 `auditBroken` 在「文件不存在」分支不复位 → 甲册审计损坏会让**无 audit.json 的乙册**被判 503；导出留痕被静默丢弃而导出仍回 200。
- **B8【数据·影像覆盖】** `assets.server.ts:592/596` 在 `replace=1` 时不查保留名 → 文件名 `<别人 id>.name.txt` 可覆盖他人指针，该单据影像 404 且文件成永不清扫的孤儿。
- **B9【前端·脏标记不复位】** `confirm-close.ts:7-21` 没有 reset 入口，`expenses.tsx:501-506` 保存后弹窗不关 → 点「关闭」仍被问「有未保存的更改」（合同/发放/人员/保险同型）。
- **B10【数据·口径分叉】** 工资条是**第 3/4 套**收款人判定（`query.tsx:101/127/360` 裸比较 `owner/name`）；守卫正则对三个受管文件 0 命中（假绿，Code Reviewer 实跑验证）。
- **B11【数据·舍入】** `round2` 的 EPSILON 修正基本无效：只在 `0≤n<2` 生效、负数方向反（`-1.005 → -1`）、`2.675→2.68` 但 `8.075→8.07`；测试只锁了 4 个正数样例。
- **B12【数据·静默归零】** 保单期结束为空 → 全员保费静默 0（测试锁定但界面无提示）；负出勤天数 → 月表页脚负工资、年度表无此人；`/api/backup` 无内容校验。
- **B13【安全·B 级若干】**（详见 `安全工程师.md`，均带 CWE 编号与最小修法）

  · CWE-922：`store.ts:628-634` 整本台账（含身份证/银行卡）明文存 localStorage；
  · CWE-284：`assets.server.ts:401-412` 删照片会连带删共享回落目录里的同名件；

## 5. 需要你拍板的项
