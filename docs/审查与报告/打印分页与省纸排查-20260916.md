# 打印分页与省纸排查（全入口，20260916，1.8.10 + 1.8.11）

> 起因：用户实测「发放记录汇总，我测试了 26 条记录打印汇总就会分页，第一页还有很多空缺就会把尾巴放在第二页」，
> 随后补一条口径：**「所有的打印都排查一下，除非打不开下一个人或者下一条记录才会出现大空白；能打开还是尽量省纸；我可以拆开分发。」**
>
> 结论：**6 个打印入口全部量过**（发放明细 / 发放汇总 / 报销单 / 保险合同清单 / 合同对账单 / 工资条），
> 1.8.10 修掉「整块被推走留下大片空白」，1.8.11 再修掉「合计每页重复」与「续页认不出是哪张单」。
> 判据不是「有没有分页」，而是**每一页填得多满**、**有没有整页空白**、**裁开之后每页认不认得出**。

---

## 1. 判据与量法（可复现，零依赖，不进构建）

| 项 | 做法 |
| --- | --- |
| 出 PDF | 真浏览器（本机 Chrome + `playwright-core`）打开**构建产物**，点真实打印按钮，`emulateMedia("print")` 后 `page.pdf({ preferCSSPageSize: true, printBackground: false, margin: 12mm })` —— 与用户 Ctrl+P 同一条排版路径、同一套 `@page` 页边距 |
| 量留白 | `ci/print-pdf.mjs`：自写 PDF 内容流解释器（只用 `node:zlib`），算每页**文字**墨迹的最低/最高点 → 底部/顶部留白 mm。外框与表格线不计（否则单据边框会被当成内容） |
| 认得出 | 同一解释器按 `/ToUnicode` CMap 解码文字，输出**每页首行/末行**，用来验证续页是否重复了表头与单据抬头 |
| 命令 | `DATA_DIR=/tmp/… PORT=4731 node app/server/index.mjs &` → `DATA_DIR=… PORT=4731 node ci/mobile-print-check.mjs pages [用例名…]` |
| 数据规模 | 2 人 / 26 笔发放（用户那条）+ 40 报销 + 40 条合同明细 + 40 参保人；另一组 45 人 / 46 笔发放（把汇总清单也压到多页） |

## 2. 1.8.10：大片空白（用户报的那条）

复现（改动前，26 笔 / 2 人，含代收折行）：**明细清单第 1 页只有一个人的记录，页底留白 112.3mm，
另一个人的整节被推到第 2 页**。三条根因：

1. 打印件里用了**容器级** `break-inside-avoid`（每个人的明细 `section`、整张对账单 `article`、小表外层 `div`）——
   页底放不下就**整块**推移，上一页留一大片空白；
2. 外壳 `.app-bg` 的 `min-h-screen/min-h-dvh` 在打印媒体里也生效（容器至少一屏高），
   `overflow-x-hidden` 在打印态等于滚动容器（会裁内容）→ 提前断页/多空白页；
3. 打印表格没有跨页表头规则，第 2 页起没有表头。

修法（规则集中到 `src/styles.css` 的「打印分页协议」一处）：一屏高清零 + `.app-bg { overflow: visible }`；
「不许拆页」下沉到**行/小单元**（`.print-only tr`、`.print-keep`）；`.print-only thead { display: table-header-group }`。

## 3. 1.8.11：两条「拆开分发」才暴露的问题

### 3.1 合计行被浏览器印在每一页页脚（口径）

- **复现**：45 人台账 → 发放「汇总清单」2 页：第 1 页只有第 1~32 行，页底却印着
  `总计（全部实际收款人）46 笔 ¥343,500.00`；保险合同清单 2 页：第 1 页只有 29 人，页底印着**全单**合计 `10,691.53`。
- **根因**：`tfoot` 的 UA 默认值是 `table-footer-group`，分页媒体下浏览器按规定在**每一页**页脚重复它。
- **修法**：`.print-only tfoot { display: table-row-group }`（`src/styles.css`）→ 整单合计只在表格结束时出现一次。
- **实测**（同一份 PDF 按文字位置统计）：汇总「总计」第 1 页 **1 处 → 0 处**（第 2 页仍 1 处）；
  保险「合计」第 1 页 **1 处 → 0 处**（第 2 页 2 处：明细表 + 按班组汇总表，都合法）。

### 3.2 续页认不出是哪张单（可用性）

- **复现**（改动前每页首行）：保险合同清单第 2 页 `序号 姓名 队长 开始日期 结束日期 使用天数 保费(元)`；
  合同对账单第 2 页 `收款`；报销单第 2 页 `序 购 买 时`（列标题）。
  用户要**拆开分发**，这些续页拿到手里不知道属于哪张保单 / 哪份合同 / 谁的报销。
- **修法**：把**单据抬头搬进 `<thead>` 第一行**（表头本来就跨页重复）：
  · 保险：`团体保险人员清单 · PICC-2026-0001 · XX小区二期团体意外险 · 队长：… · 在保`（唯一实现 `policyCaption()`，明细表与「按班组汇总」都带）；
  · 合同对账单：每张小表带 `合同对账单 GD-2026-001 · 开票`（`MiniTable` 新增 `caption`）；
  · 报销单：表头带 `报销人：… · 收款人：… · 开户行：… · 打款账户：…`（原来那张独立小表并进表头，第 1 页行数不变）。
- **效果**：第 1 页**不多占行**（抬头原来也在），只有续页顶上多一行（≈4mm，续页本来就空着）。
  实测续页首行变成：保险 `团体保险人员清单 · PICC-2026-0001 · …`、合同 `合同对账单 GD-2026-001 · 开票`、
  报销单 `报销人：张建国 · 收款人：木工一班 · 开户行：— · 打款账户：—`。

## 5. 已知取舍（未改，等用户决定）

**工资条**仍是「一张或两张一页 + 中间裁切线」的设计（`.payslip` 是唯一允许容器级不拆页的例外）。
单个人的内容超过一页时（例：9 个月考勤 + 14 笔打款，约 303mm 高），会印成 **2 页，第 2 页只有
「领款人签字」一行**（实测该页留白 268.3mm）。这是「一人一张、便于签字裁剪」的取舍；
若要与其它单据一致地「续排填满」，需要重排工资条版式（去掉 flex 拉伸、允许表体跨页），
属版式改动，本轮按用户「不好定夺的让我来确定」的口径留给用户拍板。
