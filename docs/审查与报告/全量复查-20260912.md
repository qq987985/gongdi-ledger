## 一、已修复（本轮改动，逐条可核对）

### 1. 弹窗「防误关」形同虚设 —— 一致性问题（核心）

规范 §6.3 要求编辑弹窗一律 `useGuardedClose`：改过内容后关闭要先确认。
实际各页只有**点遮罩和按 Esc** 走了 `requestClose`（带脏检查），
而**「取消 / 关闭 / ×」按钮全部直接调 `onClose`**，绕过确认——填了一半点「取消」照样丢。
一个工具里同一个弹窗，三种关法两种口径，是最典型的「不像同一个工具」。

| 文件 | 位置 | 修复 |
|---|---|---|
| `src/routes/people.tsx` | PersonEditor 的「取消」按钮与右上角「×」（原 ~414/425 行） | 改调 `requestClose` |
| `src/routes/expenses.tsx` | ExpenseEditor 的「关闭」（原 ~962 行） | 改调 `requestClose` |
| `src/routes/contracts.tsx` | ContractEditor 的「关闭」（原 ~585 行） | 改调 `requestClose` |
| `src/routes/payments.tsx` | PaymentEditor 的「关闭」（原 ~431 行） | 改调 `requestClose` |
| `src/routes/insurance.tsx` | Modal 标题栏「关闭」（原 ~132 行）+ 三个弹窗底部的「取消」按钮（原 ~646/688/727 行） | 标题栏改 `requestClose`；新增 `ModalCloseCtx` + `ModalCancelButton`，弹窗内取消按钮统一走脏检查 |

说明：脏检查在 `confirm-close.ts`，未改过内容时 `requestClose` 直接关闭，**不弹确认、无副作用**；
只有真改过才问一句「有未保存的更改，确定关闭吗？」。

### 2. 保险页弹窗样式与其它页不一致 —— 一致性问题

`insurance.tsx` 的 Modal 用 `bg-black/40 p-4 items-center max-w-md`（居中浮层），
其它所有页统一 `bg-ink/35 p-0 md:items-center md:p-6`（移动端底部抽屉、桌面居中、`max-h-screen` 滚动）。
已把保险 Modal 改成同款容器与面板类。这是视觉上「进入的不是同一个工具」的直接来源。

### 3. 弹窗顶部按钮顺序统一到规范 §6.3

规范规定从左到右：**删除（danger）→ 取消/关闭（outline）→ 保存（主按钮）**。
实际 `people.tsx` 合规，而报销/合同/发放三个编辑器都是「关闭在最左、删除夹在中间」。
已把 `expenses.tsx`、`contracts.tsx`、`payments.tsx` 的按钮重排为规范顺序
（打印等辅助 outline 按钮放在删除与关闭之间），五处编辑器现在同一排布。

### 4. `round2()` 三处分裂 —— 金额口径问题

规范 §4 要求金额一律 `round2()`（带 EPSILON 防 0.1+0.2 误差），唯一实现应在 `src/lib/wage.ts:189`。
实际 `expenses.tsx`（原 ~82 行）和 `contracts.tsx`（原 ~1109 行）各自又写了一个**无 EPSILON** 的本地 `round2`；
`insurance.tsx` 更有 10 处手写 `Math.round(x * 100) / 100`。
已全部删除/替换，统一从 `~/lib/wage` 导入带 EPSILON 的版本。

### 5. `today()` 本地重复定义

`insurance.tsx`（原 ~16 行）手写的 `today()` 与 `dates.ts` 的 `localToday()` 逐字节相同。
已删除本地版，改用 `localToday`（日期解析必须集中在 `dates.ts`，规范 §4）。

### 6. 考勤月表改了不保存就丢 —— 防丢数据

`attendance.tsx` 的 MonthTable 是本地 state，只有「保存本月」落盘；
而「返回总览」（原 ~40 行）和月份下拉（原 ~50 行）直接切走，**未保存的修改静默丢失，无任何提示**。
已加脏检查：MonthTable 用「当前行 vs 初始快照」算出 dirty 并上报（`onDirtyChange`），
保存成功后因 store 数据回流自动回到干净态；切月/返回前弹「本月考勤有未保存的修改，确定离开吗？」；
并在「保存本月」按钮旁加了「有未保存的修改」小字提示。

### 7. 操作记录页改/删不查 `res.ok` —— 失败静默

`audit.tsx` 管理员「保存」（原 ~172 行 PUT）与「删除」（原 ~200 行 DELETE）不看响应，
失败（如 403/500）也照样弹「已保存」。已补 `r.ok` 检查，失败 `toast.error` 并保留编辑态。

## 四、规范本身的问题（用户要求一并指出）

1. **§6.3 与现实的差距曾长期没人发现**：规范写了「取消/关闭走 requestClose」，
   但四个页面全部只在遮罩/Esc 上生效 —— 说明**纯文本规范挡不住这类回退**。
   建议：给 `tests/api-guards.test.ts` 这类「约定守卫」再加一条静态扫描：
   弹窗组件里出现 `onClick={onClose}` / `onClick={onCancel}` 直接挂在按钮上的，报警。
   （本轮未加，属测试增强，可下次做。）
2. **§6.10「禁止硬编码色值」过严**：`hero-banner`、Kpi 五色这类**装饰性品牌色**本来就该跨主题固定，
   全部 token 化会让四套主题长得一样、反而失去主题意义。建议把 §6.10 改为：
   「文本/背景/边框/状态色一律走 token；**装饰性品牌渐变与图表配色豁免**，但须集中在少数组件、不得散落在表单/表格里」。
3. **§10「目前覆盖 52 个用例」已过时**：实际 136 例 + 70 往返。本轮已更新为实际数字；
   建议以后这条改成「以 `pnpm test` 输出为准」，免得再脱节。
