# 班组创建、查询日期与工资计算说明（2026-11-15）

## 范围与结果

1. 人员管理提供「创建班组」，再通过下拉选择人员所属班组。独立保存无人员的班组，旧人员班组仍可选择；首尾空白只在选项中合并，不批量改写历史人员。总览同时显示空班组，真实名为「未分班组」的班组与未填写桶使用独立键并区分标签。
2. 查询日期默认按当前个人/班组和内容选择有数据的范围。考勤取月份月初/月末；工资并入相关 owner/receiver 有效已发日期，待发不扩范围。手动范围跨核对对象、内容和同册刷新保留，「按数据日期」恢复自动；切册重置，无记录明确提示。
3. 个人、班组逐月与区间工资、查询打印及工资条展示出勤工资/加班工资，并解释每月生效的日/月工资、加班折算或小时计价、餐补、其他补助、罚款/扣款、应发组成。历史月不套当前规则；屏幕计算说明位于宽表外，手机自然换行；打印以完整跨列说明保持可读。

工资数值沿用 `getWageAt → 逐笔 monthPay → 合计`。不以汇总天数重新计价；分项累计与应发的取分差额显式说明。空月保留零值行，省去重复解释；历史负工时产生的数值仍有说明，不更改 `hasContent`、自动日期及 P-09 年度可见性待决策。

本轮保留并整合接手时已有的工资分列代码，未覆盖生产资料或旧报告。前一轮分列报告见[查询工资分列](查询工资分列-20261114.md)。版本为 1.9.5，源码及生成的 app 一起交付。

## 数据契约与兼容

- 采用新增 `Team {id,name}` 列表、保留 `Person.team` 名称关联的兼容方案。替代方案是全面改为班组 ID 关联，会涉及历史考勤、筛选及导入迁移，本次没有必要扩大范围；班组改名/删除另做设计。
- 台账 schema 2 → 3，本机持久化 10 → 11。旧册缺 teams 时补空列表，人员既有班组通过选项兼容；普通升级无生产迁移脚本，也不改历史关联字段。
- 四层 types/store/nas-sync/Excel、服务端 schema、备份恢复与整本导入同步。总台账/备份的「班组列表」保存班组编号、名称，合并恢复按名称保留已有 ID，外来 ID 冲突重新生成；重复恢复幂等。
- 创建拒绝空名、超长名、重复名；服务端拒绝重复规范化名称/ID。创建/导入留审计，入口依既有 people.edit、整本保存与恢复权限。草稿绑定台账身份。
- 生产升级前沿用 data 目录备份流程；若回到旧应用，使用升级前备份恢复。旧应用无法维护新增的空班组列表，不承诺由旧版本保存后仍保留该新增字段。
