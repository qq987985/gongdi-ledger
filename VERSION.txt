[1.7.10] 2026-09-10
- 找到并修掉「一键更新一直不生效」的真正原因（1.7.8 / 1.7.9 两版都猜错了方向，这次是实测确认的）：
  更新容器要执行的那段脚本是**语法错误**的。脚本由模板字符串生成，写法里用了 "\n"，
  而模板字符串会把它变成**真正的换行**，于是生成的 .cjs 里字符串字面量跨了行，
  node 在解析阶段直接 SyntaxError 退出（stderr 没人看），容器又被 AutoRemove 删掉 ——
  界面只看到「更新已受理」，容器其实一个都没换、日志里一个字都没有。
  （1.7.6 修的是「创建更新容器时请求体被丢掉」，那次之后容器能创建了，但脚本本身跑不起来，
   所以更新始终没生效。）
  · 脚本改用 log() / fail() 统一写日志，不再有跨行的字符串字面量；
  · 新增**语法守卫测试**：把生成的脚本真的交给 JS 引擎解析一遍（new Function），
    这类「整段脚本没法运行」的错误以后不可能再溜过去。
  · 1.7.8 / 1.7.9 加的「镜像 ID 比对、按提交 sha 拉、读镜像内版本」留着 ——
    用来对付镜像加速站缓存旧 latest 是有用的，只是**不是这次的病根**（之前归因不准确，特此更正）。
- 更新容器不再「一声不响地死掉」：
  · 任务改从环境变量传、脚本走 Cmd 内联，不再依赖 data 挂载（挂载不对也不会静默退出）；
    脚本第一步就先写一行「更新容器已启动」，stdout 也写（docker logs 能看到）。
  · 启动两秒后检查它是否还活着：已经退出就**当场报错**并把它的输出贴出来（不会再默默换个空操作）。
  · 不再自动删除更新容器：失败后它还在，点「查看更新日志」能看到

- 修复飞牛「一键更新」真正的原因（本版重点，之前几版都在查这个）：
  创建更新容器时把容器配置当成了 dockerReq 的第三个参数直传，而该参数期待的是 { body: … }，

  · 现在按 { body: … } 传，并且 dockerReq 对「配置直传」这种历史写法也会兜底识别，
    不会再静默变成空请求体。
  · Docker 的错误体（{"message":"…"}）现在取成一句话显示，界面上不再出现半截 JSON。
- 测试：新增守卫用例，扫源码里所有 dockerReq 调用，第三参数必须是 { body } 或 { stream }，
  防止这个「请求体被丢掉」的错误再犯。

[1.7.4] 2026-09-10
- 一键更新改为「立刻返回 + 后台执行 + 前端轮询进度」（反代环境下必须这样做）：
  原来点更新会挂一个 1~5 分钟的长请求，反向代理（nginx 默认 proxy_read_timeout 60s）会把它
  掐断并回一个 HTML 504，浏览器解析 JSON 失败 → 只能显示兜底的「更新失败」，而服务端其实
  还在拉镜像。现在 POST 立即返回「已开始更新」，进度用 GET /api/update?status=1 轮询；
  重复点击不会起第二个更新任务。
- 同源校验兼容反向代理：除 Host 外也接受 X-Forwarded-Host（含逗号列表）。反代若把 Host 改写成
  内网地址，原来会把通过域名访问的合法更新请求判成 403「来源不一致」；被拒时会记日志并说明改法。
- 修复「一键更新」报「更新失败」却查不出原因：
  · 客户端把「请求被中断」和「服务端没给原因」一律显示成兜底的「更新失败」。现在服务端的原因
    会原样显示；请求中断时会去轮询 /api/version 核对真实版本，明确说「已更新到 x」还是「仍是 y」。
  · 更新尝试、拉镜像成功/失败、更新容器启动、后台任务异常都写 data/logs/update.log
    （容器内的更新脚本同样写），失败还会写 data/.gongdi-update-error.txt。
  · 非 Error 型异常不再产生空错误信息（空原因正是「更新失败」这四个字的来源）。
- 飞牛（Docker）更新重建容器更稳（「手动一键拉取能成、应用内更新不行」的另一半根因）：
  · 原来把 inspect 出来的整份网络配置（含 IPAddress / IPAMConfig / MacAddress / Aliases）原样
    喂回 /containers/create，不少 Docker 版本会直接报 invalid endpoint settings；现在只按网络名
    重新挂载。手动更新走的是 docker compose（由 compose 重新组装网络），所以不受影响。

  浏览器看到网络中断 → 界面报「更新失败」，而更新其实已经开始。现在先让响应发出去再退出。

- 新增「设置 → 影像归入本台账」：按本台账的人员姓名与合同/报销 id，把历史公共目录里的影像复制进来
  （只复制、不删除、不覆盖，可随时回退）。全部归入并归档旧目录后，可设 PHOTO_LEGACY_FALLBACK=off 关闭回落。
- 删除台账时会连该台账自己的影像目录一起删除。

B 台账保存更安全：
- 读台账不再回写文件（原来读一次可能顺手改写整本，绕过写队列和版本校验，会覆盖并发保存的新数据）。
- 保存冲突（409）不再只有提示：会拉取最新版本号，让你选「用本机数据覆盖服务器」或「放弃本机改动」。
- 重新加载会覆盖本机未保存改动时，先弹确认。
- 服务端校验台账结构：明显坏掉的写入（例如空对象）会被拒绝，不再可能把整本台账写坏。

C 权限：
- 权限 id 改为单一来源声明表，页面与接口写错权限名会**编译不过**（以前写错只是静默不生效）。
- 敏感导出（人员/整本/考勤/发放）需要「导出权限 + 人员查看权限」，以前只要导出权限就能导出身份证/银行卡。
- 操作记录写入要求有改动权限（只读账号不能伪造/灌水记录）。
- 保存整本台账的权限判据客户端与服务端统一：权限不足会明确提示，不再出现「提示已保存其实没存上」。

D 可观测性与数据自保：
- 新增服务端日志：data/logs/日期.log（同时输出到容器日志）。权限拒绝、保存冲突、台账/账户数据读取失败、
  操作记录写入失败都会留痕——以前这些错误被静默吞掉，事后无从查起。
- 台账文件、账户文件损坏时不再当成「空数据」：拒绝写入并在前端显示专门的提示页，
  不再引导「初始化管理员」（那会把损坏但可能可恢复的 accounts.json 覆盖掉）。
- 账户文件、操作记录文件改为随机临时名 + 串行写入（并发时不再互相覆盖或截断）。
- 操作记录补全：影像上传/更换/删除、合同明细增删、导入替换、单条发放删除等以前不留痕的操作，现在都记。

- 发版与合并解耦的做法写在 ci/README.md（需在 GitHub 网页改 workflow）。
